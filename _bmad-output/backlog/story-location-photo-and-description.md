# 收纳位置支持照片和描述，照片按需查看

## Description

家庭成员找到物品的收纳路径后，可以用位置照片和描述确认是哪一个抽屉、柜子或收纳箱，而无需把这些位置另建成物品。

## Requirements

1. **位置资料可独立编辑。**\
   **Given** 用户在「设置 → 位置管理」中创建或编辑任意层级的位置，\
   **When** 用户保存该位置，\
   **Then** 可以在现有管理入口的同一新建/编辑表单中保存名称、上级位置（编辑时只读）以及可选的描述和照片；两项均可分别替换、编辑或清除，互不影响。
   - 描述最多 300 个用户感知字符（Unicode 字素簇），换行计入；保存前去除首尾空白，全空白视为无描述；客户端与服务端使用同一规则，不静默截断。浏览页和照片弹窗完整显示描述并保留换行。
   - 照片可选，限 1 张 JPG / PNG / WebP，单张不超过 10 MB；可拍照或从设备选择，相机不可用时仍可从设备选择。
   - 已保存照片默认只显示状态文字，按需在字段内展开；展开时提供加载中、失败、重试和收起，不叠第二个弹窗。
   - 新建/编辑共用表单替代现有的行内重命名；保存只由「保存」按钮触发，取消/关闭按现有表单行为丢弃未提交修改。

2. **浏览不主动展示照片。**\
   **Given** 用户在位置树或列表中浏览，\
   **When** 用户选中一个位置，\
   **Then** 树和列表仍只显示文字；「浏览」页直接显示该位置的描述（如有），描述全文保留换行，随页面滚动，不折叠、不截断，也不自动移动焦点或滚动页面；仅在位置元数据表明有照片时提供「查看位置照片」，点击前不请求照片文件。
   - 「是否有照片」来自位置元数据，不通过试探图片 URL 判断；元数据可随位置或物品数据请求，但照片文件请求必须延后到用户点击。
   - 切换位置只更新描述、入口和物品筛选；长位置树的可达性在实现后人工验收，不改变现有树的键盘模型。

3. **从物品详情直接查看。**\
   **Given** 用户打开物品详情，\
   **When** 物品的收纳位置有照片，\
   **Then** 在收纳位置旁显示同一个「查看位置照片」入口，点击前不请求位置照片；没有位置照片时不显示入口。入口紧跟在收纳路径后，空间不足时自然换行到路径下方，不进入或替代物品照片区。

4. **按需查看且不打断浏览。**\
   **Given** 页面显示「查看位置照片」，\
   **When** 用户点击入口，\
   **Then** 才加载并在共用弹窗中展示照片、完整位置路径和描述（如有）；弹窗只有正文纵向滚动，标题栏和底部操作区固定，关闭始终可见，无横向裁剪；照片按 contain 完整显示。
   - 加载失败时提示失败并提供重试，路径、描述、关闭仍可用；关闭后保留原页面、筛选、滚动位置和焦点，焦点回到触发入口；触发入口不存在时回到可聚焦的回退容器。
   - 支持可见 X、「关闭」按钮和 Esc；不抢占 Android/浏览器返回键，返回键维持原导航语义。弹窗打开/关闭不改 URL。
   - 加载/错误文本与重试控件分开播报，避免把按钮并入警报文本。
   - 新增或变更控件的点击区域至少 44×44 CSS px；既有位置树、物品卡和物品照片区不重做。

5. **失败的换图不丢旧照片。**\
   **Given** 位置已有照片，\
   **When** 替换照片失败，\
   **Then** 用户能看到明确的失败提示，原照片仍可查看并可重试。
   - 新建时位置/描述已保存、照片失败：表单切换为编辑该新位置，保留本地预览，提示可重试或稍后补传；再次保存只更新，不重复创建。
   - 失败、部分成功或结果未知时，状态提示或重试控件获得焦点并滚入视口；提示常驻，不自动消失。
   - 服务端提交结果未知（超时/响应丢失）时，不断言旧照片一定未改；提示用户关闭后重新打开或刷新元数据再判断，不自动重复提交。不要求新增幂等系统，但未知创建不能诱导用户直接重提。
   - 移除照片与编辑描述相互独立；组合操作失败时，明确哪些内容已保存、哪些未完成，不把已保存内容报成失败。

6. **删除空位置不波及其他照片。**\
   **Given** 位置没有子位置和物品，\
   **When** 用户确认删除该位置，\
   **Then** 该位置的描述和照片随位置一起清理；位置照片与物品照片双向隔离，删除位置不影响物品照片，删除物品也不影响位置照片。
   - 现有非空删除限制保持不变；非空位置删除失败时，位置、描述和照片都保持原样，不先删照片再报错。
   - 组合删除或清理失败时给出可见反馈，不误报已删除。

## Boundaries

- 不改变现有位置层级、物品归属、按位置筛选或物品照片的行为；删除位置仍受现有非空限制。
- 不做多图相册、位置分类、描述搜索、图片搜索、重新挂载父位置、离线排队上传或全屏照片路由。
- 不强制新增 API DTO、字段名或工具类；照片有无只要求来自位置元数据。
- 不改变位置树现有键盘模型，不抢占 Android/浏览器返回键。
- 全新数据库必须能创建所需结构。不要求兼容、保留、迁移或回填旧业务数据；本票不授权清理任何实际环境的数据。

## Verify

Verify: 使用隔离的临时 SQLite 数据库和图片目录，不访问现有 `data/`、业务数据库或图片。通过应用现有建库流程创建所需结构，不迁移或回填旧业务数据。按下列 1–8 项验收。

1. **描述独立保存：** 在同一父位置下创建两个位置并分别关联物品。分别保存描述、清空描述、只改照片，确认两字段互不影响；描述换行在浏览页和弹窗中原样显示，300 字边界按 Unicode 字素簇计算，首尾空白去除后全空保存为无描述，客户端与服务端结果一致且无静默截断。
2. **照片添加/替换/移除：** 添加、替换、移除各一次；刷新后状态正确。另测格式不支持和超过大小上限，确认提示明确，已保存的照片不变。替换时注入服务端已开始处理新照片、但在提交生效前的确定性失败（仅拒绝非法文件不算），重新打开后仍看到旧照片，并可重试。再模拟一次提交结果未知（超时或响应丢失），确认 UI 不断言旧照片一定未改，而是重新获取已保存的状态后再判断。
3. **按需加载：** 在「浏览」选中位置、打开物品详情、以及位置管理展开已保存照片之前，网络记录中不得出现位置照片文件请求；位置元数据请求可以存在。点击后才出现图片请求。
4. **两个入口：** 浏览页有描述时显示全文；有照片时才显示入口。无描述时不显示空标签；无照片时不显示入口。物品详情入口紧跟收纳路径，物品无照片时仍可出现，位置照片不进入物品照片区。
5. **失败与焦点：** 位置照片加载失败时，弹窗内路径/描述仍可读，错误文本与「重试」分开，X 和「关闭」始终可见；Esc、可见关闭、背景点击均可关闭，关闭后筛选、滚动和焦点保留。管理表单保存失败/部分成功/结果未知时，提示条或重试控件获得焦点并滚入视口。
6. **相机与取消：** 在移动浏览器分别验证允许、拒绝、用户取消、无相机设备。仅在检测到真实相机错误时显示「无法使用相机，请从设备选择照片。」；用户取消不显示该错误；「从设备选择」始终可用。
7. **删除隔离：** 准备编号相同且各自有照片的空位置和物品，物品放在另一个位置。分别在独立的样本中删除空位置或删除物品，确认另一方的照片仍可查看，且删除空位置后只清理它自己的描述和照片。删除非空位置仍被拒绝，位置、描述和照片不变。
8. **窄屏与无障碍（实现后）：** 分别验证 320 CSS px 宽、200% 文本缩放、横屏和增大文本间距：无横向滚动，保存、取消、关闭、重试及照片入口均可达。用键盘和读屏验证焦点、加载与失败反馈；实测新增或变更控件至少 44×44 CSS px。用长位置树验证信息面板可达。静态稿本身不构成通过证据。
