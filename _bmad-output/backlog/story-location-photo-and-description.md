# 收纳位置支持照片和描述，照片按需查看

## Description

家庭成员找到物品的收纳路径后，可以用位置照片和描述确认是哪一个抽屉、柜子或收纳箱，而无需把这些位置另建成物品。

## Requirements

1. **位置资料可独立编辑。**\
   **Given** 用户在「设置 → 位置管理」中创建或编辑任意层级的位置，\
   **When** 用户保存该位置，\
   **Then** 可以为它保存一张照片和一段描述；两项均可选，可分别替换、编辑或清除，互不影响。
2. **浏览不主动展示照片。**\
   **Given** 用户在位置树或列表中浏览，\
   **When** 用户选中一个位置，\
   **Then** 树和列表仍只显示文字；「浏览」页直接显示该位置的描述（如有），有照片时才提供「查看位置照片」，点击前不请求照片文件。
3. **从物品详情直接查看。**\
   **Given** 用户打开物品详情，\
   **When** 物品的收纳位置有照片，\
   **Then** 在收纳位置旁显示同一个「查看位置照片」入口，点击前不请求位置照片；没有位置照片时不显示入口。
4. **按需查看且不打断浏览。**\
   **Given** 页面显示「查看位置照片」，\
   **When** 用户点击入口，\
   **Then** 才加载并在弹窗中展示照片、完整位置路径和描述（如有）；若照片加载失败，提示失败且仍可关闭弹窗。关闭后保留原页面和筛选状态。
5. **失败的换图不丢旧照片。**\
   **Given** 位置已有照片，\
   **When** 替换照片失败，\
   **Then** 用户能看到失败提示，原照片仍可查看。

Verify: 从全新 SQLite 数据库启动，创建同一父位置下的两个位置，并分别关联物品。验证描述单独保存、照片添加/替换/移除、替换失败、两个查看入口、点击前后的网络请求，以及位置照片与物品照片互不影响。

## Boundaries

- 不改变现有位置层级、物品归属、按位置筛选或物品照片的行为；删除位置仍受现有的非空限制。
- 不做多图相册、位置分类或描述搜索。
- 全新数据库必须能创建所需结构。不要求兼容、保留、迁移或回填旧业务数据；本票不授权清理任何实际环境的数据。
