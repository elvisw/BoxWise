# BoxWise 收纳位置 — Experience Spine

> Story #1 的行为契约；视觉身份见 `DESIGN.md`。静态稿在 `mockups/`，只确认布局与关键状态，行为以本文件和 `DESIGN.md` 为准。

## Foundation

单套响应式 Web PWA（Blazor WASM + MudBlazor），家庭成员在室内使用，手机优先、桌面可用；沿用现有 AppBar、底部导航和页面外壳，不新增页面或导航项。所有使用者都是已登录家庭成员，本功能不新增权限门槛。浅色主题，无深色模式。

**范围。** 位置描述与位置照片的新建/编辑；浏览页选中位置后的描述；浏览与物品详情中的「查看位置照片」入口；位置管理表单内的已保存照片预览（含加载/失败/重试）；浏览与物品详情共用的位置照片弹窗；删除空位置时清理其描述和照片。物品自身的缩略图和详情照片保持现状，本设计只规定它们与位置照片的区分。

**不做。** 新页面、全屏照片路由、多图/相册、位置照片搜索、描述搜索、重新挂载父位置、旧数据迁移/回填、离线排队上传、幂等系统、抢占 Android/浏览器返回键、改变位置树现有键盘模型。验收从全新隔离 SQLite 与全新图片目录启动，不设计旧数据迁移/回填 UI，也不授权清理任何实际环境的数据。

**术语。**

| 术语 | 含义 |
|---|---|
| 位置照片 | 绑定在位置节点上的一张照片，用于辨认抽屉/柜子/箱子；不是物品照片，不进入物品照片区。 |
| 位置描述 | 绑定在位置节点上的一段可选文字；为空即没有描述。 |
| 位置路径 | 从根位置到当前节点的完整名称链，视觉显示为 `A → B → C`。 |
| 位置元数据 | 随位置（或物品的收纳位置）取得的描述和「是否有照片」状态；具体字段/接口形状由实现决定，不要求新增 DTO 或工具类。 |
| 查看位置照片 | 查看已保存照片的入口。在浏览和物品详情中打开共用弹窗，在位置管理表单中展开预览。点击前不请求照片文件。 |
| 新选照片 | 用户在表单里选中、尚未保存的本地图片；只在本机预览。 |
| 已保存位置照片 | 已写入位置的照片；在点击「查看位置照片」前不加载。 |
| 用户感知字符 | Unicode 字素簇；用于 300 字上限，不按 UTF-16 单元或码点计数。 |

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 设置 → 位置管理 | 设置页「位置管理」 | 新建/编辑位置名称、上级位置、描述、照片；删除空位置 |
| 浏览 | 底部导航「浏览」 | 按位置/标签筛选物品；选中位置后显示描述，有照片时显示「查看位置照片」 |
| 物品详情 | 物品卡/浏览结果 | 查看物品；位置路径旁显示同一个「查看位置照片」入口 |
| 位置照片弹窗 | 浏览位置信息面板 / 物品详情入口 | 按需加载并展示已保存照片、完整路径、描述；关闭回到原处 |

不新增页面。位置照片弹窗是覆盖层，不是路由；打开/关闭不改变 URL、不重置筛选。弹窗只叠一层，沿用现有 `MudDialog` 的模态行为。位置管理中的「查看位置照片」在表单内展开已保存照片预览，不打开第二个弹窗；避免在管理对话框上再叠一层。

描述和「是否有照片」来自位置元数据，随位置数据加载；入口可见性不通过试探图片 URL 判断。只有用户点击查看后才请求已保存的位置照片：在浏览和物品详情中打开共享弹窗，在位置管理中展开表单内预览。物品详情必须能获得其收纳位置的照片有无；实现可以选择随物品数据返回或加载位置元数据，但不得为了判断入口而请求照片文件。

本轮无 imports；静态稿见 `mockups/`。

## Voice and Tone

微文案。品牌语气与视觉姿态见 `DESIGN.md.Brand & Style`。

| Do | Don't |
|---|---|
| 「查看位置照片」 | 「查看照片」「位置主图」「封面」 |
| 「已保存位置照片」 | 把已保存照片做成缩略图或角标 |
| 「新选照片（未保存）」 | 让新选照片看起来已经保存 |
| 「正在加载位置照片…」 | 只显示一个无文字的转圈 |
| 「位置照片加载失败。」 + 「重试」 | 「网络错误」作为唯一提示 |
| 「位置已创建，照片未上传。可重试或稍后补传。」 | 位置已创建却说「创建失败」，让用户重新创建 |
| 「名称和描述已保存，照片替换失败。原照片仍保留。」 | 「上传失败」而不说旧照片是否还在 |
| 「照片移除失败，原照片仍保留。描述已保存。」（仅在服务端确认描述已保存时） | 组合操作失败时不说哪些内容已保存，或把未确认内容报成已保存 |
| 「位置和描述已保存，照片状态暂时无法确认。请关闭后重新打开核对。」 | 把超时或响应丢失说成「照片未上传」或「原照片仍保留」；在整次保存结果未知时断言资料已保存 |
| 「描述不能超过 300 字。」 | 显示实时剩余字数、倒计时，或静默截断输入 |
| 「照片超过 10 MB，请换一张更小的图片。」 | 「上传失败」而不说大小限制 |
| 「无法使用相机，请从设备选择照片。」 | 用户取消也报相机故障，或隐藏「从设备选择」 |
| 「暂时无法确认是否创建成功。请关闭表单查看位置列表。如果该位置已出现，请编辑它并补传照片，不要再次创建。」 | 把超时/响应丢失说成「保存失败，请重新创建」 |
| 「删除位置会同时移除它的描述和照片；有子位置或物品时无法删除。」 | 「确定删除？」而不说会删什么 |
| 「暂无物品」等现有空状态 | 在浏览页加「暂无描述」占位 |
| 短句、具体对象、说清下一步 | 感叹号、庆祝语、emoji、泛泛的「操作成功」 |

## Component Patterns

行为规格。视觉规格见 `DESIGN.md.Components`。

| 组件 | 使用位置 | 行为规则 |
|---|---|---|
| 位置资料表单 | 设置 → 位置管理 | 新建从「添加位置」或行内「+」进入；编辑从行内铅笔图标进入，表单预填名称、描述和照片状态。新建与编辑共用同一表单；新建时上级位置可选，编辑时上级位置只读，不提供移动/重新挂载。名称必填并有可见「（必填）」；描述、照片可选。保存只通过「保存」按钮触发，多行描述里的回车不提交。取消/关闭只丢弃当前表单里未提交的修改，不删除已保存的位置、描述或照片；不新增离开拦截或自动保存。标题栏与底部操作区固定，表单正文滚动，「保存」「取消」始终可达。 |
| 位置描述字段 | 位置资料表单 | 多行输入；上限和计数规则见 Data Contracts。不显示实时字符计数，不在输入时静默截断；辅助说明写明上限，超过上限时字段下方显示「描述不能超过 300 字。」并阻止保存，直到回到上限以内。空值保存为「无描述」。只改描述不影响照片；清空描述也不移除照片。保存后浏览页选中该位置即可看到描述全文，保留换行。 |
| 位置照片字段 | 位置资料表单 | 从「拍照」或「从设备选择」添加一张，格式和大小见「Data Contracts」。检测到相机错误时提示改用设备选图；取消不视为相机错误。校验失败不改变已保存照片或已有本地预览。已有照片默认只显示状态文字；点「查看位置照片」才展开并加载。换图时预览新选照片，旧照片仍可按需展开对比。选择新文件或标记移除时收起旧照片预览；移除成功保存后才生效。 |
| 已保存照片预览（表单内） | 位置资料表单 | 「查看位置照片」是 disclosure：用 `aria-expanded`/`aria-controls` 表示展开状态；展开后焦点留在按钮，按钮可见文字变为「收起」并带可访问名称「收起位置照片」。展开时才请求图片。加载中显示进度指示和「正在加载位置照片…」，用 polite 状态播报；失败显示「位置照片加载失败。」和「重试」，错误文本用 alert 播报，重试按钮是错误文本的兄弟节点、不在 alert 内；「收起」始终可用，不自动收起，不清掉「已保存位置照片」状态。重试成功后替换为图片；重试失败保留错误与收起。收起后再次展开可重新请求。预览图片使用已保存照片的 alt；不移动焦点，不叠弹窗。 |
| 本地照片预览 | 位置资料表单 | 只在文件通过格式与大小校验后预览浏览器本地选中的文件，不请求服务器；明确标注「新选照片（未保存）」。取消选择、取消表单或保存成功后清除预览；照片上传失败时预览保留，供重试。 |
| 浏览位置信息面板 | 浏览 | 选中位置且有描述或有照片时出现；描述在前，入口在后。没有描述就不显示「描述」标签或占位；没有照片就不显示入口。切换选中位置立即更新；取消选中/清空筛选时消失。面板本身不触发照片请求。描述全文保留换行，随页面正常滚动；不设内部最大高度、不折叠、不截断，也不在选中后自动跳焦点或自动滚入视口。长描述把标签/结果自然推到下方，用户按正常页面滚动查看。 |
| 位置照片入口 | 浏览位置信息面板、物品详情 | 文案固定为「查看位置照片」；仅在位置元数据表明有照片时显示。可见性来自位置元数据，不通过请求图片 URL 试探；元数据暂不可用时不显示入口，也不回退为图片探测。点击前不请求照片文件；点击后打开共享弹窗。浏览页的入口在信息面板底部；物品详情的入口紧跟位置路径，空间不足时自然换行，物品详情的编辑模式不显示。入口消失/出现不改变页面布局的其他部分。 |
| 位置照片弹窗 | 浏览、物品详情 | 浏览与物品详情共用；位置管理不打开此弹窗（改用表单内预览）。打开时才请求已保存照片，展示完整路径、照片、描述（如有）。标题栏与底部操作区固定，正文是唯一纵向滚动容器；X 和「关闭」始终可见、可聚焦；Esc 可关闭，背景点击可关闭，不抢占 Android/浏览器返回键。照片横/竖/方都按 contain 完整显示，空余留白，不裁剪、不拉伸、不横向滚动。加载中显示指示；失败显示「位置照片加载失败。」+「重试」，错误文本与重试控件分开，路径/描述仍在。关闭不导航、不刷新、不重置筛选或滚动位置，焦点回到触发入口；触发入口不存在时回到可聚焦的回退容器。不提供多图、缩放、轮播或下载按钮。 |
| 位置删除确认 | 位置管理 | 沿用行内确认，不新增确认弹窗。确认文案说明会同时移除描述和照片，以及非空位置无法删除；后果说明用 `aria-describedby` 关联。确认出现时焦点移到确认容器或第一个按钮，Esc 取消并把焦点还给删除图标。只有空位置（无子位置、无物品）能删除；成功时位置、描述、照片一起清理，物品照片不受影响；失败时位置、描述、照片都保持原样，不先删照片再报错。删除结果未知时不断言已删除，重新加载位置元数据再判断。 |
| 状态提示条 | 位置资料表单、保存流程 | 需要用户处理的失败/部分成功/结果未知用常驻提示条，不自动消失；图标 + 文字，文字用正文色，图标用 error/success。文字与动作（「重试上传」「重试」「关闭提示」）分开播报，重试控件不在 alert 文本内。任何状态都不能只靠颜色。完整成功可用现有 `MudSnackbar` 短暂提示；若现有 snackbar 不能可靠播报，使用持久 polite 状态节点。 |
| 字段错误 | 位置资料表单 | 位于对应字段下方；错误文字与字段通过 `aria-describedby` 关联，设置 `aria-invalid="true"`，静态辅助说明也纳入 `aria-describedby`。错误出现时用持久 polite/alert 区域播报一次（去抖），不逐字符播报；修正后清除无效状态，不必反复播报「已修正」。名称必填、描述超限、照片格式/大小、相机不可用都同时有图标和文字。 |
| 物品照片区 | 物品卡、物品详情 | 保持现状：物品卡缩略图、物品详情大图、无照片占位都不变。位置照片永远不进入此区域，也不替代物品照片；物品没有照片时，位置照片入口仍可独立存在。 |
| 位置树 | 浏览 | 保持现状：只显示文字，不显示位置照片缩略图、不显示照片角标。选中节点驱动浏览位置信息面板和物品筛选；不因照片有无改变树的结构、排序或现有键盘模型。长树在实现后人工验收面板与入口可达性。 |

## Data Contracts

**描述（用户已确认）。**

| 字段 | 约束 |
|---|---|
| 位置描述 | 可选；最多 300 个用户感知字符（Unicode 字素簇）；换行计入；保存前去除首尾空白，去除后全空白视为无描述；客户端与服务端使用同一规则；不静默截断。浏览页和照片弹窗完整显示并保留换行。 |
| 位置照片 | 可选；每个位置最多 1 张；JPG / PNG / WebP；单张 ≤10 MB；可拍照或从设备选择；相机不可用时仍可从设备选择。 |

**保存结果语义。** 「保存失败」指服务端明确返回失败/未写入；「保存结果未知」指超时或响应丢失，不能断言未写入。两者分开处理。照片状态未知时，不断言旧照片未改；关闭后重新打开或刷新位置元数据再判断，不自动重复提交。

**资料独立性。** 描述和照片是两个独立字段，保存一个不覆盖另一个。

| 操作 | 描述 | 照片 |
|---|---|---|
| 只保存描述 | 更新 | 不变 |
| 只保存照片 | 不变 | 成功时替换；失败时保留原照片 |
| 清空描述 | 移除 | 不变 |
| 移除照片 | 不变 | 成功时移除；失败时保留 |
| 照片上传失败 | 已保存的描述保留 | 原照片保留 |
| 移除照片失败 | 仅在服务端确认描述已保存时保留并说明；无法确认时提示刷新核对 | 原照片保留 |
| 名称/描述保存失败 | 原描述保留 | 原照片保留 |
| 保存/上传结果未知 | 不断言未保存，也不断言已保存 | 不断言原照片未改；重新核对元数据 |

**删除隔离。** 位置照片与物品照片互不级联。

| 操作 | 位置描述/照片 | 物品照片 |
|---|---|---|
| 删除空位置 | 一起移除 | 不变 |
| 删除非空位置 | 被拒绝，位置/描述/照片都不变 | 不变 |
| 删除物品 | 不变 | 按现有行为移除 |
| 替换位置照片 | 成功时替换旧照片 | 不变 |
| 删除结果未知 | 不断言已删除，重新加载元数据再判断 | 不变 |

## State Patterns

### 位置管理

| 状态 | 处理 |
|---|---|
| 冷加载 | 沿用现有对话框加载指示；列表出现后不请求照片。 |
| 无位置 | 沿用「暂无位置，请添加第一个位置」。 |
| 新建空闲 | 空白表单；名称为空或描述超过上限时「保存」不可用，并显示原因；描述/照片可选。 |
| 新建保存中 | 「保存」禁用并显示进行中；不重复提交。 |
| 新建完整成功 | 关闭表单、刷新列表；提示「位置资料已保存」；再次打开编辑时照片状态为「已保存位置照片」文字，不加载图片。 |
| 新建部分成功 | 位置和描述已保存、照片失败：表单不关闭，切换为编辑该新位置；常驻提示「位置已创建，照片未上传。可重试或稍后补传。」；保留本地预览；焦点移到提示条或「重试上传」并滚入视口；再次保存只更新，不重复创建。 |
| 照片上传结果未知（超时/响应丢失，前提：位置/描述保存已确认） | 提示「位置和描述已保存，照片状态暂时无法确认。请关闭后重新打开核对。」；重新读取服务端状态后再决定是否重试，不重复创建位置。若整次保存结果未知，按「新建/编辑结果未知」处理，不断言已保存。 |
| 新建完全失败 | 服务端明确返回失败：表单保留全部输入；提示「保存失败，位置资料没有保存。」；服务器无新位置；焦点移到提示条并滚入视口。 |
| 新建结果未知（超时/响应丢失） | 表单保留输入；提示「暂时无法确认是否创建成功。请关闭表单查看位置列表。如果该位置已出现，请编辑它并补传照片，不要再次创建。」；不自动重新提交，也不断言未保存；焦点移到提示条并滚入视口。 |
| 字段校验失败 | 描述超过上限、照片格式不支持或超过 10 MB 时，在对应字段下方显示错误并阻止保存；已保存照片、已有本地预览和表单其他输入不变。 |
| 相机不可用/权限拒绝 | 仅在检测到真实设备/权限错误时显示「无法使用相机，请从设备选择照片。」；「从设备选择」保持可用；焦点留在来源按钮组。 |
| 用户取消相机/选图 | 不显示相机故障文案；照片状态和已有预览不变；焦点回到来源按钮组。 |
| 编辑空闲（有照片） | 显示「已保存位置照片」文字，不加载图片；描述预填；「查看位置照片」可用，点开后字段内展开预览，不打开弹窗。 |
| 编辑（展开已保存照片·加载中） | 字段内显示进度指示和「正在加载位置照片…」；「收起」可用；不自动收起，不叠弹窗。 |
| 编辑（展开已保存照片·失败） | 字段内显示「位置照片加载失败。」+「重试」；错误文本与重试控件分开播报；「收起」可用；不显示破图，不清掉「已保存位置照片」文字。 |
| 编辑（新选照片） | 显示本机预览与「新选照片（未保存）」；旧照片仍可查看；提示保存后替换。 |
| 编辑（待移除照片） | 显示「照片将在保存后移除」+「撤销移除」；保存前旧照片仍可查看。 |
| 编辑保存中 | 按钮禁用；不重复提交。 |
| 编辑完整成功 | 关闭表单、刷新列表；提示已保存；照片状态更新。 |
| 编辑部分成功（替换失败） | 表单不关闭；提示「名称和描述已保存，照片替换失败。原照片仍保留。」；旧照片仍可查看；焦点移到提示条或「重试上传」并滚入视口；可重试上传或取消选择。 |
| 编辑部分成功（移除失败） | 仅在服务端明确返回描述已保存、照片移除失败时，提示「照片移除失败，原照片仍保留。描述已保存。」；若无法确认描述是否保存，提示刷新核对，不把未确认内容报成已保存；表单不关闭；旧照片仍可查看；可重试移除或撤销移除。 |
| 编辑失败 | 服务端明确返回失败：表单保留输入；名称/描述未写入；旧描述、旧照片不变；焦点移到提示条。 |
| 编辑结果未知（超时/响应丢失） | 不说不保存；保留输入与旧照片状态，提示关闭后重新打开核对；不自动重复提交。 |
| 移除照片失败 | 旧照片保留；提示失败；可重试；若同次描述已保存，明确说明描述已保存。 |
| 删除确认 | 行内显示后果说明；「删除」与「取消」都可见；焦点进入确认区域；Esc 取消。 |
| 删除成功 | 行消失；提示已删除；该位置的描述/照片清理。 |
| 删除非空失败 | 沿用现有非空错误；行、描述、照片都保持。 |
| 删除结果未知 | 不断言已删除；重新加载位置列表/元数据后判断，不自动重试。 |
| 提示条可见性 | 失败/部分成功/结果未知时，提示条或重试控件获得焦点并滚入视口；提示条常驻，只有用户主动关闭才消失。 |

### 位置照片弹窗

| 状态 | 处理 |
|---|---|
| 打开/加载中 | 立即显示完整路径和描述；照片区域显示进度指示和「正在加载位置照片…」；不自动重试。焦点移入弹窗，读屏播报弹窗名称和路径；焦点规则见「Accessibility Floor」。 |
| 加载成功 | 显示完整照片（contain，不裁剪）；路径、描述保持可读；X 与「关闭」可用。 |
| 横图/竖图/方图 | 均按 contain 等比完整显示；横图上下留白、竖图左右留白、方图居中；不裁剪、不拉伸、不横向滚动。 |
| 加载失败 | 照片区域显示「位置照片加载失败。」+「重试」；错误文本播报与重试按钮分开；路径、描述仍在；X 与「关闭」仍可用。 |
| 重试 | 重新进入加载中；成功后替换错误；失败后保留错误与关闭。 |
| 关闭 | 不导航、不刷新、不重置筛选/滚动；焦点回到触发入口；触发入口不存在时回到可聚焦的位置树当前节点容器或物品详情标题容器。 |
| 长路径/长描述 | 路径与描述换行；正文纵向滚动，标题栏和底部操作区固定；X 或「关闭」至少一个无需滚动即可见；不横向滚动。 |
| 照片文件缺失 | 按加载失败处理，不显示破图图标。 |
| 权限拒绝 | 不适用：所有已登录家庭成员都可查看位置照片；本功能不新增权限。 |
| 离线 | 不做离线承诺；照片加载沿用网络失败处理，不排队、不缓存新上传。 |
| 系统返回键 | 不拦截；维持现有 Android/浏览器返回语义。关闭使用可见 X、「关闭」、Esc 或背景点击。 |

## Interaction Primitives

- **触屏。** 新操作均可直接点击，不依赖悬停、长按或拖拽。
- **键盘。** Tab 顺序跟随阅读顺序，Enter/Space 激活按钮；Esc 关闭照片弹窗或取消行内删除确认。描述字段按 Enter 换行，不提交表单。不新增全局快捷键。
- **弹窗。** 一次只开一层，打开时背景不可交互；不新增历史记录，也不拦截系统返回键。关闭和焦点规则见下方「Accessibility Floor」。
- **手势。** 不要求双指缩放、滑动切换照片或下拉刷新；浏览器缩放保持可用。表单、相机和状态提示的行为见「Component Patterns」。

## Accessibility Floor

行为层目标 WCAG 2.2 AA；视觉对比度见 `DESIGN.md.Colors`。

- **弹窗。** 使用 `role="dialog"` / `aria-modal`，可访问名称为「位置照片」，用关联的路径说明播报完整路径，不读视觉箭头，也不重复朗读路径。描述是可导航文本，不在打开时自动朗读全文。打开后焦点落到可聚焦的标题或容器，Tab 焦点不离开弹窗。X 的可访问名称为「关闭位置照片」。关闭后等页面稳定，再把焦点还给入口；入口不存在时聚焦预先配置的回退容器。
- **可见关闭。** X 和「关闭」同时存在；加载中、失败、长内容滚动时也保持可见、可聚焦、可点击（至少一个无需滚动即可见）。
- **表单内预览。** 展开按钮语义见「Component Patterns」的「已保存照片预览（表单内）」。浏览和物品详情入口打开弹窗，不使用 `aria-expanded`。
- **状态播报。** 加载中用持久 polite 区域播报「正在加载位置照片」；失败用 alert 播报错误文本；重试按钮是 alert 的兄弟节点，避免把按钮并入警报文本。成功/部分成功用 polite 播报，不重复轰炸；「保存结果未知」也播报，但不断言未保存。状态同时有文字，不靠颜色。
- **图片替代文本。** 已保存照片 `alt` 为「已保存位置照片：<完整位置路径>」；新选照片为「新选位置照片预览（未保存）：<完整位置路径或文件名>」；两种图不共用 alt。路径和描述以文本提供，不把关键信息只放在图片里。加载失败时不留下破图 alt。
- **表单。** 标签与字段关联；名称必填并有可见「（必填）」和 `aria-required`；描述可选且上限见 Data Contracts；静态 helper 与动态错误都进入 `aria-describedby`；错误时设置 `aria-invalid`；不用 placeholder 代替标签；不显示实时计数器，不在输入时逐字播报，超限/格式/大小错误出现时播报一次（去抖）。保存按钮禁用时同时显示原因。
- **照片来源。** 「位置照片（可选）」用 `fieldset`/`legend` 或 `role="group"` + `aria-labelledby` 组成字段组，限制说明作为组的 `aria-describedby`；相机权限失败用 polite 播报，焦点留在来源按钮组，可继续选图；用户取消不播报故障。
- **触控与缩放。** 新增/变更操作目标至少 44×44 CSS px；200% 文本缩放、320 CSS px 宽、横屏下路径、描述换行，照片等比缩小，弹窗/表单正文纵向滚动，不出现横向滚动；按钮不用 `white-space:nowrap` 锁死，长名称/路径用 `overflow-wrap:anywhere`。
- **焦点可见。** 沿用 MudBlazor 焦点环，不自定义移除 outline；删除与取消按钮之间有足够间距，避免误触。
- **减弱动态。** 不新增动画；加载指示沿用 `MudProgressCircular`；无自定义过渡需要适配 reduced motion。

## Responsive & Platform

| 条件 | 行为 |
|---|---|
| 320 CSS px 宽 / 400% reflow | 单列；表单/弹窗正文滚动，保存、取消、X、关闭、重试、入口均可达；无横向滚动；长路径/名称换行。 |
| 200% 文本缩放 | 按钮文字换行，固定高度改 `min-height`；标题栏/操作区仍可见，正文可滚动；触点不被裁剪。 |
| 文本间距（1.4.12） | 调整行高、字距、词距后文本不裁剪、不重叠；按钮和字段随内容增高，不锁死固定高度。 |
| xs（<600px） | 位置资料表单全宽；字段纵向排列；描述错误和照片提示在字段下方换行；浏览顺序为位置树 → 信息面板 → 标签筛选；物品详情入口在路径下方换行；弹窗接近全宽，照片最大高度 `min(60vh, 60dvh)`，关闭保持 44px。 |
| sm–md（600–1279px） | 浏览恢复现有两列；信息面板仍在位置树下方同一列；物品详情入口可同行；弹窗使用 Medium 宽度。 |

| 横屏手机 | 弹窗高度受动态视口限制，照片让位于路径/描述；正文滚动，关闭/重试/保存可达；不横向滚动。 |

PWA/平台：沿用现有安装、底部导航和安全区处理；弹窗操作区不被底部导航遮挡。触屏与键盘能力对等；不新增原生应用行为、通知或离线队列。系统返回键维持原导航语义；可见关闭与 Esc 是弹窗关闭方式。静态稿不能替代 320px、200%、横屏、键盘和读屏的真实应用验收。

## Inspiration & Anti-patterns

- **沿用 BoxWise 现有语言：** 位置树作为筛选主入口；物品卡/详情的照片语言；`MudDialog` 的模态层。位置照片只在需要辨认「哪一个」时出现。
- **Rejected — 位置照片做物品缩略图/详情主图：** 会让「是什么」和「在哪里」混在一起，也会让浏览页重新变成图片流。
- **Rejected — 选中位置就自动加载照片/自动跳焦点/自动滚到面板：** 违反按需加载，也打断长树和长描述下的正常浏览；描述已经能回答大多数问题。
- **Rejected — 折叠/截断/内部滚动长描述：** 300 字上限内应完整可读；用正常页面滚动，不制造第二层滚动。
- **Rejected — 新增全屏照片页面或路由：** 会打断浏览筛选和物品详情上下文；共用弹窗即可。
- **Rejected — 在管理对话框上再叠照片弹窗：** 两层模态会让焦点和关闭路径变复杂；表单内展开预览即可。

## Key Flows

### Flow 1 — 位置资料可独立编辑（林岚，周三 20:40，书房）

1. 林岚在设置页打开「位置管理」，点「添加位置」。
2. 在同一个表单里填名称「右侧抽屉」，选上级位置「书桌」。
3. 描述分两行写「充电线、备用电池和说明书；左侧是空的。」，点「从设备选择」，从手机相册选一张抽屉内部照片。
4. 表单显示「新选照片（未保存）」和本机预览；没有请求服务器。
5. 点「保存」。位置和描述先保存成功，照片随后上传成功。
6. **Climax:** 表单关闭，列表出现「右侧抽屉」，但没有缩略图。她可以立刻继续添加下一个位置；重新打开编辑表单时，照片字段只显示「已保存位置照片」，不自动加载照片。
7. 稍后她再次编辑这个位置，只清空描述并保存；照片仍是「已保存位置照片」，互不影响。

失败：位置和描述保存成功、照片上传失败 → 表单不关闭，切换为编辑这个新位置，提示「位置已创建，照片未上传。可重试或稍后补传。」，本机预览保留；焦点移到提示条或「重试上传」并滚入视口；再次保存只更新，不重复创建。若名称/描述保存本身失败 → 表单保留输入，服务器无新位置，原数据不变。

### Flow 2 — 浏览不主动展示照片（周启，周六 10:15，找充电线）

1. 周启打开「浏览」；位置树只显示文字。
2. 他展开「书房 → 书桌」，点「右侧抽屉」；物品列表按该位置筛选。
3. 位置树下出现浏览位置信息面板，显示描述全文「充电线、备用电池和说明书；左侧是空的。」并保留两行换行；面板底部有「查看位置照片」文字入口，但没有缩略图或图片占位。
4. 他没有点入口，直接按描述拉开右侧抽屉，在里面找到充电线。
5. **Climax:** 整个过程中没有请求位置照片；描述已经足够回答「哪一个抽屉」。面板没有自动跳焦点或滚动，长描述随页面正常滚动。

失败：位置数据加载失败 → 沿用现有「加载位置失败」，不显示信息面板，也不请求照片；物品列表仍按现有错误/空状态处理。位置元数据暂时不可用时入口不显示，也不通过图片 URL 试探。

### Flow 3 — 从物品详情直接查看（周启，周六 10:20，物品详情）

1. 他在浏览结果里点「USB-C 充电线」。
2. 物品详情显示物品照片（或现有「暂无照片」占位）和「位置: 书房 → 书桌 → 右侧抽屉」。
3. 位置路径后紧跟「查看位置照片」文字入口；入口不在物品照片区，也不替代物品照片。长路径下入口自然换行到路径下方。
4. 他点击入口；位置照片弹窗打开，先显示完整路径和描述，照片区域显示加载指示。
5. 照片加载完成，显示抽屉内部照片，按 contain 完整展示，不裁剪。
6. **Climax:** 他对照照片里的左侧隔层，确认充电线就在那里；弹窗没有把他带离物品详情。

失败：照片加载失败 → 弹窗内显示「位置照片加载失败。」和「重试」，路径/描述仍在，X 与「关闭」可用；关闭后焦点回到「查看位置照片」，页面和物品详情不变。系统返回键不被拦截，用户使用可见关闭或 Esc。

### Flow 4 — 按需查看且不打断浏览（林岚，周日 09:05，浏览页）

1. 林岚在浏览页选中「厨房 → 吊柜 → 保鲜盒」，并按标签「烘焙」筛选。
2. 她点「查看位置照片」；弹窗加载照片、完整路径和描述。
3. 她关闭弹窗（X、「关闭」或 Esc）。
4. **Climax:** 位置树仍选中「保鲜盒」，标签筛选仍是「烘焙」，滚动位置没变，焦点回到「查看位置照片」；她可以直接点下一个位置的照片，不需要重新筛选。

失败：照片加载失败 → 她仍可关闭；关闭后筛选、滚动和焦点同样保留；入口不因失败消失，可再次尝试。长描述在弹窗正文内纵向滚动，标题栏和底部操作区固定，关闭始终可见。

### Flow 5 — 失败的换图不丢旧照片（林岚，周日 09:20，编辑位置）

1. 她在位置管理里编辑「保鲜盒」，看到「已保存位置照片」文字，图片没有自动加载。
2. 她点「查看位置照片」，表单内展开旧照片预览；若图片加载中，显示「正在加载位置照片…」，失败则显示错误与「重试」。确认是哪一个盒子后点「收起」。
3. 她点「更换照片」，选了一张新照片；表单显示「新选照片（未保存）」和本机预览，并提示「保存后替换现有照片」。
4. 她点「保存」。名称/描述保存成功，新照片上传明确失败。
5. **Climax:** 提示「名称和描述已保存，照片替换失败。原照片仍保留。」；她展开预览确认旧照片还在，可以重试上传或取消选择。
6. 如果她改用「移除照片」，按钮变为「撤销移除」；保存成功后，浏览/物品详情不再显示入口；保存失败则旧照片仍保留。

失败：如果名称/描述保存也失败 → 表单保留全部输入，旧描述和旧照片不变；如果她取消选择 → 回到「已保存位置照片」，旧照片不变。
结果未知时，按「State Patterns」重新核对已保存状态，不自动重试。

### Flow 6 — 删除空位置不波及其他照片（林岚，周日 09:40，位置管理）

1. 她发现「旧收纳箱」已经空了，点该行的删除图标。
2. 行内显示待删除位置「旧收纳箱」及说明「删除位置会同时移除它的描述和照片；有子位置或物品时无法删除。」焦点进入确认区域。
3. 她点「删除」。
4. **Climax:** 位置从列表消失；它的描述和照片一起清理；物品照片没有变化。她又试删一个还有物品的位置，系统按现有非空限制拒绝，位置、描述、照片都还在。

失败：非空位置沿用现有错误提示，位置、描述和照片不变。删除结果未知时，重新读取位置列表再核对。

### Flow 7 — 拍照权限失败后改选设备图片（林岚，周日 09:30，编辑位置）

1. 她在编辑「右侧抽屉」，点「拍照」，浏览器询问相机权限。
2. 她拒绝权限；应用检测到相机错误后显示「无法使用相机，请从设备选择照片。」，「从设备选择」仍可用。
3. 她点「从设备选择」，选了一张 JPG；文件通过格式与大小校验，字段显示「新选照片（未保存）」和本机预览。
4. **Climax:** 她仍能完成这次照片更新，不需要离开表单或重新打开页面；已保存照片在保存成功前仍可查看。

失败：设备选图也取消 → 不显示相机故障文案，字段回到原来的「已保存位置照片」状态，不产生上传请求；如果选中的文件格式不支持或超过 10 MB → 字段下方显示对应错误，旧照片和已有预览不变。
