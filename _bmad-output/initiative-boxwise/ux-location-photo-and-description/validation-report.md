### High (7)

**「状态覆盖」/ 无障碍 M4（重复项，合并）— 管理表单内已保存照片预览没有加载中 / 失败 / 重试状态**（`EXPERIENCE.md:89`、`147-148`、`200`；`DESIGN.md:155`；`review-accessibility.md` M4）

只有照片弹窗写了「内容纵向滚动」；管理对话框新增提示条、名称、上级位置、三行以上描述、照片字段、展开预览与操作按钮后高度显著增加，但两张草图的 `.dialog-body` 都是 `overflow: hidden`。200% 文本或 320px 宽下，300 字描述 + 展开预览 + 提示条可能超出对话框，保存/取消、路径/描述/重试落在裁剪区，键盘焦点还可能移到被裁剪控件上。静态稿固定 390×844，不能证明滚动行为，但对话框内容区的 `overflow:hidden` 不是画框装饰，容易被照抄。

**「无障碍 H2」— 保存失败 / 部分成功提示可能出现在视口外**（`DESIGN.md:161`；`EXPERIENCE.md:95`、`141-144`；`.working/key-manage-location.html:507-513`、`553-556`）
提示条固定在表单上方，保存按钮在表单底部。用户在窄屏或 200% 下滚到底点击保存时，失败/部分成功/结果未知的常驻提示可能完全在视口之外；部分成功还会把表单从「新建」切换为「编辑该新位置」，这是一次较大的重渲染，却未规定切换后的焦点与滚动位置。读屏用户可能通过 live region 听到提示，低视力键盘用户仍可能看不到，像「什么都没发生」。
*Fix:* 失败/部分成功/结果未知时，将焦点移到提示条（`tabindex="-1"`）或其中的「重试」按钮并滚入视口；不要在保存按钮旁复制一套不一致文案，若要加摘要必须与顶部同源；部分成功切换时保留滚动位置或聚焦表单标题/提示条，并播报「位置已创建，照片未上传」；提示条保持常驻，仅由用户主动关闭，关闭后仍能从字段状态看出照片未保存。

**「无障碍 H3」— 44×44 触控契约没有落到各组件规格**（`EXPERIENCE.md:195`、`215`；`DESIGN.md:54`、`158`；`.working/key-manage-location.html:114`、`222`、`238`、`263`、`308`；`.working/key-browse-location.html:118-129`、`140`；`.working/key-item-detail.html:141`；`.working/key-photo-dialog.html:113`、`181`）

*Fix:* 在 `DESIGN.md.Components` 逐项写明 44×44 最小点击区域（含 padding，而非只看文字高度），覆盖 X、关闭、重试、保存、取消、拍照、从设备选择、查看位置照片、收起、查看现有位置照片、撤销移除、重试上传、关闭提示、行内删除/取消；实现用 `min-height:44px` + `min-width:44px` 并检查相邻间距；或更新草图尺寸，或在每张草图顶部标注「示意图不按 1:1 表达触控尺寸，以 DESIGN.md 为准」；验收用浏览器 computed box 实测，不用「CSS 写了 min-height」代替。树节点是既有控件，本次不要求重做，但新入口不要继承 32px 树行高度。

### Medium (17)

*Fix:* 为输入框单列满足 3:1 的 `border-control` token；或明确输入框由 MudBlazor 的标签/填充承担识别、`line-default` 只用于分隔线，并补该例外的对比度说明。

**「组件覆盖」— `字段错误` 缺行为侧组件行**（`DESIGN.md:162`；`EXPERIENCE.md:88-89`、`145`）
`字段错误` 在 DESIGN 有独立视觉行，但 EXPERIENCE Component Patterns 没有对应行，行为散落在描述字段/照片字段行和 `字段校验失败` 状态里。下游无法从组件表直接读出错误的放置、字段关联、播报和消失规则。
*Fix:* 在 Component Patterns 增加一行「字段错误」，或明确把它折叠进两个字段行并删除 DESIGN 的独立组件名。

**「状态覆盖」— 移除照片失败的组合状态未定义**（`EXPERIENCE.md:112-119`、`153`、`156`）
「移除照片失败」只写「旧照片保留；提示失败；可重试」，没有说明同一次保存里已修改的描述是否已保存、表单是否留在编辑态。`资料独立性` 表与 `编辑部分成功` 只覆盖「替换失败」。
*Fix:* 明确「描述已保存 + 移除失败」：表单不关闭、旧照片仍可查看、描述以服务端状态为准，并给出下一步文案。

**「状态覆盖」— 照片上传结果未知缺已承诺的微文案**（`EXPERIENCE.md:76`、`142`、`156`）
唯一的结果未知文案是新建场景的「暂时无法确认是否保存成功。请关闭表单查看位置列表；若已出现该位置……」，但此时位置和描述已保存、位置一定存在，这句话不适用；`EXPERIENCE.md:142` 只描述行为没有给文案，移除照片失败也没有独立文案。
*Fix:* 为「位置/描述已保存、照片状态未知」和「移除照片失败」各加一条固定文案，放进 Voice and Tone 与状态表。

**「精简与过度规格」— 组件行用原始 px 复述 token**（`DESIGN.md:153`、`155`、`157`、`159-163`）
`12px` 对应 `{spacing.3}`、`8px` 对应 `{spacing.2}`、`4px` 对应 `{spacing.1}`、`4px 圆角` 对应 `{rounded.sm}`。改 token 时这些行不会跟着变。
*Fix:* 组件行改用 token 引用，或只写一次「下列数值是当前解析结果，实际以 token 为准」。

**「精简与过度规格」— 300 字与照片限制被反复重述**（`DESIGN.md:154`、`183`；`EXPERIENCE.md:88`、`105`、`138`、`145`、`198`、`213`、`330`、`336`；照片限制见 `DESIGN.md:155`、`184`；`EXPERIENCE.md:89`、`106`、`198`、`334`、`337`）
约束一旦调整，容易只改一处。
*Fix:* 以 Data Contracts 表为唯一 canon，其余位置只保留状态特有的行为，用交叉引用代替复述。

**「继承纪律」— 物品详情的 `hasPhoto` 来源未定义**（`EXPERIENCE.md:46`、`92`、`173-174`）
入口可见性来自「位置元数据中的 hasPhoto 标记」，描述和是否有照片随位置数据加载；但物品详情只列了有/无照片状态，没有说物品详情 DTO 是否带 `locationHasPhoto`，还是需要额外取位置元数据。
*Fix:* 明确数据来源（随物品 DTO 返回，或加载位置元数据），并写进「点击前不请求照片文件」的验收。

**「继承纪律」— 「300 字」的计数单位与空白描述语义未定义**（`DESIGN.md:154`；`EXPERIENCE.md:88`、`105`、`330`）
没有说按 Unicode 码点、字素簇还是 UTF-16 单元计数，换行是否计入；「空值即无描述」也没有说全空白是否按空处理。
*Fix:* 定义计数单位、换行是否计入，以及 `Trim()` 后为空是否即无描述；客户端与服务端使用同一规则并纳入验收。

**「无障碍 M1」— 焦点返回只有意图，没有实现机制**（`EXPERIENCE.md:187`、`207`；`DESIGN.md:178`）
契约要求关闭弹窗后焦点回到触发入口，入口不存在时回到位置树当前节点或物品详情标题。但没有说明 Blazor/MudBlazor 中如何实现：触发入口可能在重渲染中被替换，保存的 `ElementReference` 可能失效；`MudDialog` 默认焦点恢复不一定回到业务按钮；普通 `<h2>` 没有 `tabindex="-1"` 不能通过程序化 `FocusAsync()` 接收焦点；树节点也需要可聚焦引用。若依赖浏览器默认行为，焦点可能回到 body。
*Fix:* 打开前保存触发元素引用，关闭后在 `OnAfterRenderAsync` 中聚焦；元素不存在时聚焦带 `tabindex="-1"` 的标题/容器；为物品详情标题与位置树当前节点明确可聚焦回退；把鼠标、键盘 Enter/Space、Esc、背景点击、失败后关闭各测一次焦点列入验收。

**「无障碍 M2」— 选择位置的 live region 位置矛盾**（`EXPERIENCE.md:91`、`169`、`210`、`212`）
契约要求选择变化后信息面板以 `aria-live="polite"` 播报「已选择 <位置名称>」，但面板只在「有描述或有照片」时出现，两者都无时不渲染。如果 live region 就是面板：无内容时不播报；面板每次切换被移除/重新插入，播报可能丢失；若 live region 包住整个面板，会把 300 字描述一次读完，与「不强制一次朗读长文」矛盾；快速方向键切换还可能排队播报每个节点。
*Fix:* 在浏览页放一个持久的、视觉隐藏的状态节点，只播报简短状态（如「已选择右侧抽屉。有描述，有位置照片。」），面板本身不是 live region；快速切换做去抖或稳定后播报，初次加载/默认选中不播报；描述保持普通可导航文本；表单状态条同原则，避免 `role="alert"` 与 `aria-live` 同时挂在同一节点造成双播报。

**「无障碍 M3」— 已保存照片与新选照片可能使用相同 alt**（`EXPERIENCE.md:89`、`209`、`211`；`DESIGN.md:155`）
已保存照片 alt 为「位置照片：<完整位置路径>」，管理表单内展开的预览又称「使用同样的 alt」。编辑已有照片并选择新文件后，界面可同时显示新选本地预览和展开的旧照片，两张不同图片同名，读屏用户无法区分哪张已保存、哪张未保存；也让「替换失败后原照片仍保留」难以用读屏确认。
*Fix:* 已保存照片用「已保存位置照片：<路径>」，新选照片用「新选位置照片预览（未保存）：<路径>」（可含文件名）；每张预览与其可见状态文字放在同一带标签的组里；加载失败时不要保留旧 alt 或破图。

**「无障碍 M5」— 表单必填、上限、静态说明与动态错误的读屏信息不完整**（`DESIGN.md:153-155`；`EXPERIENCE.md:87-88`、`138`、`213`；`.working/key-manage-location.html:386-389`）
只写「名称必填」，组件规格和草图都没有可见的「必填」标记；视力正常用户也要等到「保存」不可用才知道。禁用按钮通常不可聚焦，读屏用户可能听不到它，也听不到禁用原因。静态 helper「最多 300 字」「1 张，JPG/PNG/WebP，≤10 MB」没有纳入 `aria-describedby`；动态错误只写「字段下方显示」和 `aria-describedby`，没有明确插入时如何播报。
*Fix:* 名称标签加可见「（必填）」并提供 `aria-required="true"`；静态 helper 与动态错误都纳入字段 `aria-describedby`，错误时设 `aria-invalid="true"`；动态错误用持久 polite/alert 区域去抖播报一次，修正后清除 invalid 但不必反复播报；若保留禁用保存，给按钮关联原因说明或附近摘要，或改为提交时聚焦第一个错误字段；照片格式/大小错误同样播报。

**「无障碍 M6」— 「位置照片（可选）」不是程序化字段组**（`DESIGN.md:155`；`.working/key-manage-location.html:401-406`）
组件规格称其为「带标签『位置照片（可选）』的字段组」，草图却用 `<p class="photo-label">`，「拍照」「从设备选择」没有 `fieldset`/`legend`/`role="group"`/`aria-labelledby`。读屏用户按 Tab 只听到两个按钮，不知道它们属于位置照片、可选、限一张与格式大小。
*Fix:* 用 `fieldset` + `legend`（或 `role="group"` + `aria-labelledby`）包住来源按钮和状态文字；限制作为组的 `aria-describedby`；错误/相机失败提示与组关联。

**「无障碍 M7」— 弹窗失败态把重试按钮包在 `role="alert"` 内**（`.working/key-photo-dialog.html:432-437`；`EXPERIENCE.md:185`、`210`）
`role="alert"` 放在整个 `.photo-frame.failure` 上，里面同时有错误标题、说明文字和「重试」按钮。alert 是给文本的 live region；把交互控件放进去，读屏可能把按钮名称当作整段警报朗读，或在重试时重复朗读整块，跨读屏/浏览器行为不一致。契约要求失败用 alert 播报并显示重试，但没有规定两者的 DOM 关系。
*Fix:* 只把错误文本设为 `role="alert"`（或放进持久的 `aria-live="assertive"` 区域），「重试」按钮作为兄弟节点放在 live region 外；重试时更新同一错误节点，不重新插入整块；失败态下路径、描述、X 和「关闭」仍可用。

**「无障碍 M8」— 信息面板位于整棵树之后，长树 + 长描述会拉远选中节点**（`DESIGN.md:128`；`EXPERIENCE.md:91`、`223`；`.working/key-browse-location.html:235-246`）
已确认布局是「信息面板在位置树下方、同一列内」，本报告不要求移动。但草图只有 4 个节点，真实家庭可能有几十个位置；选中靠近树顶的节点后，面板和「查看位置照片」入口可能在整棵树之后，200% 下要滚动几个视口，低视力用户可能不知道下方出现了描述。若 `MudTreeView` 不是单一 Tab 停靠点，键盘用户按 Tab 还要穿过每个节点；300 字不截断会进一步推远「按标签」与物品结果。
*Fix:* 保持面板在树下；明确 `MudTreeView` 使用 roving tabindex/单一 Tab 停靠点，Tab 从树直接进入面板入口；指针选中后将面板滚入视口（不移动焦点），或在树旁提供「已选择 X · 查看信息」链接；用 30 个节点 + 300 字在 200%/320px 下验证；不要单方面改「不截断」。

**「无障碍 M9」— 声称 WCAG 2.2 AA，但只覆盖 200%**（`EXPERIENCE.md:205`、`215`、`221-225`）
WCAG 2.2 AA 的 1.4.10 Reflow 要求 320 CSS px 宽（1280px 下 400% 缩放），1.4.4 要求 200% 文本缩放，1.4.12 要求文本间距调整后不丢内容。当前 Responsive 表只定义 xs <600、sm–md、lg+，没有 320px/400%/文本间距/横屏的验收条件；草图 `.btn { white-space: nowrap; line-height: 1 }` 和固定高度在 200% 文本/1.4.12 间距下可能裁剪。
*Fix:* 在 Responsive & Platform 或 Accessibility Floor 增加验收矩阵：320×640、200% 文本、1.4.12 文本间距、横屏手机；标准为无横向滚动、所有操作可达、焦点不被遮挡、文本不被裁剪；允许按钮标签换行，固定高度改 `min-height`，长路径/名称加 `overflow-wrap:anywhere`；若本轮只做到 200%，就不要把 WCAG 2.2 AA 写成无条件目标。

**「无障碍 M10」— 相机权限回退的判定路径未定义**（`EXPERIENCE.md:146`、`199`、`214`；Flow 7 `309-316`；`DESIGN.md:155`）
文案、焦点保持、`aria-live` 播报都写得很清楚：相机不可用/权限拒绝时显示「无法使用相机，请从设备选择照片。」，「从设备选择」保持可用。但没有定义应用如何知道相机不可用/权限被拒绝。移动浏览器上 `<input type="file" capture>` 被拒绝或取消时，常见结果是「没有文件」；把用户取消误判为相机失败会错误提示；真实拒绝若没有触发事件，承诺的提示可能永不出现。
*Fix:* 明确检测路径（`navigator.mediaDevices.getUserMedia`/`MediaDevices` 错误，还是文件输入的 `change`/`cancel` 事件），只对真实可观测的权限/设备错误显示相机专用文案；用户取消时不显示「无法使用相机」，保持原照片状态，焦点回到来源按钮组；「从设备选择」始终可用；在 iOS Safari、Android Chrome 上测允许/拒绝/取消/无设备四种情况；浏览器无法可靠区分拒绝与取消时，保留两个按钮和静态提示，不要断言未观察到的失败。

### Low (10)

**「状态覆盖」/ 无障碍 L8（重复项，合并）— 弹窗的系统/浏览器返回键行为未定义**（`EXPERIENCE.md:44`、`93`、`187`、`197`；`.working/key-photo-dialog.html:460`；`review-accessibility.md` L8）
设计承诺不改 URL、关闭后保留筛选，但关闭方式只列了 X、「关闭」、Esc 和背景点击。手机 PWA 上按返回键可能直接离开浏览页，违背「关闭不导航、不重置筛选」。
*Fix:* 明确 Back 是关闭弹窗还是离开页面；若要关闭，push 一个历史条目并在 `popstate` 中关闭，且不改 URL/不重置筛选；在 Android Chrome 验证返回键与手势返回；若不支持关闭，明确写出并纳入验收。

**「精简与过度规格」— `物品照片区` 复述现有实现的尺寸**（`DESIGN.md:163`）
150px/400px 是既有代码细节，不是本功能的视觉契约，会随现有物品照片样式变化而漂移。
*Fix:* 只保留「位置照片不进入该区域、不替代物品照片」的分离规则，尺寸引用现有组件行为即可。

**「继承纪律」— 术语表「唯一」与表单对比入口文案不一致**（`EXPERIENCE.md:29`、`89`；`DESIGN.md:155`）
术语表说「查看位置照片」是「唯一的已保存照片查看入口文案」，但表单的新选照片状态使用「查看现有位置照片」。
*Fix:* 把「唯一」限定为浏览/物品详情入口，或统一表单里的对比入口文案，并说明表单内是 disclosure、不是弹窗。

**「无障碍 L1」— 弹窗可访问名称使用视觉箭头「→」**（`EXPERIENCE.md:212`；`.working/key-photo-dialog.html:258`、`314`、`371`、`425`）
契约要求路径的可访问文本是「位置路径：A，B，C」，但草图 `aria-label` 直接使用「书房 → 书桌 → 右侧抽屉」。若实现用视觉字符串拼 `aria-label`/`alt`，读屏可能读「向右箭头」或产生不自然停顿。
*Fix:* 用独立的可访问路径格式化函数生成「A，B，C」；视觉箭头用 CSS `::before` 或 `aria-hidden` 包裹；确保路径不会在名称、正文、alt 中被重复朗读三次。

**「无障碍 L2」— 「收起」失去对象上下文，disclosure 与弹窗触发易混淆**（`EXPERIENCE.md:209`；`DESIGN.md:155`；`.working/key-manage-location.html:469`）
展开后按钮名变为「收起」，用户导航到别处再回来只听到「收起」不知道收的是什么；同一文案「查看位置照片」在浏览/物品详情是打开弹窗，在管理表单是 disclosure，实现时容易给错误的一方加 `aria-expanded`。
*Fix:* 可见文字保留「收起」，提供 `aria-label="收起位置照片"`；`aria-expanded`/`aria-controls` 仅用于管理表单的 disclosure；浏览/物品详情的触发按钮保持普通 button 语义。

**「无障碍 L3」— 行内删除确认缺少焦点/播报/Esc 契约**（`EXPERIENCE.md:94`、`157`；`DESIGN.md:160`）
新增了「该位置的描述和照片也会移除；有子位置或物品时无法删除」的后果说明，但没有写确认出现后焦点去哪、读屏如何知道、Esc 是否取消、取消后焦点回到哪。键盘用户可能仍停在删除图标上。
*Fix:* 确认出现时把焦点移到确认容器（`tabindex="-1"`）或第一个按钮；用 `aria-describedby` 关联后果说明；Esc 取消并把焦点还给删除图标；「删除」与「取消」保持 44px 和足够间距。

**「无障碍 L4」— `60vh`、`nowrap`、长不可断字符串的窄屏风险**（`DESIGN.md:130`、`159`；`.working/key-photo-dialog.html:161-191`；`.working/key-manage-location.html:232`）
移动浏览器动态工具栏下 `vh` 可能大于可见视口，60vh 照片 + 固定头尾会挤压路径/描述；`white-space:nowrap` 和固定 `line-height:1` 在 200% 文本/1.4.12 间距下可能裁剪；长位置名或长路径没有 `overflow-wrap` 可能撑出横向滚动。
*Fix:* 用 `max-height: min(60vh, 60dvh)` 或 `60svh`；新按钮允许换行，不锁 `nowrap`；长路径/名称用 `overflow-wrap:anywhere` 和 `min-width:0`；照片区用 `min-height` 而非固定高度。

**「无障碍 L5」— 物品详情「同行/换行」缺少明确断点**（`DESIGN.md:129`；`EXPERIENCE.md:326`；`.working/key-item-detail.html:243-246`）
设计写「空间足够时同行，空间不足时换行到路径下方，上边距 8px」；草图里路径是 `display:block`，入口始终在下一行。实现者不知道「空间足够」的判定条件，可能出现两种不一致行为。
*Fix:* 定义入口为路径行内的 inline-flex、随文本自然换行，换行时 `margin-top: 8px`；或给出明确断点；在草图中同时展示同行和换行两种状态。

**「无障碍 L6」— 成功提示可能只靠 MudSnackbar**（`EXPERIENCE.md:95`、`210`）
完整成功可以用现有 MudSnackbar 短暂提示，无障碍要求成功用 `aria-live="polite"` 播报。如果 MudSnackbar 本身没有被读屏播报，或 3 秒内消失，读屏用户会错过「已保存」。
*Fix:* 验证 MudSnackbar 在当前 MudBlazor 版本中的 live-region 行为；不可靠时增加持久 polite 状态节点，或让成功消息保留到下一次操作；不要只依赖短暂 snackbar。

**「无障碍 L7」— 弹窗打开后的焦点落点未指定**（`EXPERIENCE.md:207`）
只写「打开后焦点进入弹窗」，没有说进入标题、正文还是 X。若默认聚焦 X，读屏会先听到「关闭」；若聚焦 body，键盘用户要再 Tab 才能关闭。两种都能用，但行为不确定，验收无法一致。
*Fix:* 指定焦点落点为对话框标题/容器（`tabindex="-1"`）或 X；若落在 X，确保对话框的可访问名称（含「位置照片」和路径）在进入时先被播报，X 本身仍叫「关闭」；保证 Esc 在打开后立即可用，Tab 焦点循环。

## 静态稿边界（不记为缺陷）

以下在四张 HTML 中看起来「不可用」，但属于静态低保真稿的预期占位；真正的实现以 `EXPERIENCE.md` / `DESIGN.md` 的契约和真实组件为准：

- 所有操作看起来都是 `<span>`：保存/取消、X、底部「关闭」、「重试」、「查看位置照片」、「拍照」、「从设备选择」等。静态稿没有 JS，不能测试键盘、焦点、文件选择或相机。
- 静态稿没有 `aria-expanded`、`aria-live`、`aria-invalid`、focus-visible 样式、disabled 语义；这些缺失是「静态视觉稿不表达行为」，不是契约缺口。
- 固定 390×844 的 `.screen`/`.phone` 外框和 `overflow:hidden` 是示意手机的画框，不能用来判断真实页面滚动；但 `.dialog-body { overflow:hidden }` 是对话框内容区本身，与 H1 的滚动契约冲突，不能照抄。
- `key-photo-dialog.html` 只有第 1 帧有 `aria-describedby`（`:258`），第 2–4 帧没有（`:314`、`:371`、`:425`）；这是静态稿内部不一致，实现时应统一为「标题 `aria-labelledby` + 描述/路径 `aria-describedby`」。
- 草图中的图标大多没有 `aria-hidden="true"`；真实实现中纯装饰图标应隐藏，带文字的按钮不要让图标产生额外可访问名称。
- 草图的颜色/对比度是 token 声明，不是渲染测量；静态稿不能替代真实对比度测量。
