# PRD: 箱知 · BoxWise

## 0. Document Purpose

本文档是 BoxWise v1 的产品需求文档，面向开发者本人及家庭成员。文档基于 2026-05-21 头脑风暴会话的结论构建，Glossary 锚定术语体系，功能按模块分组、FR 全局编号。内联 `[ASSUMPTION]` 标记推断项，统一索引至 §11。本文档不重复头脑风暴中已完成的因果分析和技术选型论述。

## 1. Vision

**箱知 · BoxWise** 是一个 PWA Web APP，解决一个日常但令人沮丧的问题：不常用的东西收纳起来后，过了很久想用却找不到——而且不只是你找不到，你的家人也找不到。

问题的根源不在于收纳本身，而在于收纳动作是一次性的、无反馈闭环的——物品被放好的那一刻，就是信息丢失的开始。人脑没有记忆过期提醒机制，BoxWise 在收纳完成的那一刻介入，用持久化数字记录代偿人脑做不到的两件事：**持久记录**和**即时检索**——让全家人都能受益。

BoxWise 只做一件事：让家里的每个人在需要的时候，搜一下、看一眼，就知道东西在哪。不扩展搬家、资产清单、断舍离——就只是"我的东西在哪"。

## 2. Target User

### 2.1 Primary Persona

核心用户是开发者本人及其家庭成员——会把不常用物品"安全地藏起来"然后全家人都找不到的人。场景是搬家后、大扫除后、换季整理后，物品被分散收纳到不同房间、柜子、箱子里，记忆随时间衰减。家庭成员之间信息不对称：收纳的人知道在哪，其他人完全不知道。

### 2.2 Jobs To Be Done

- 收纳时：花最少的时间记录"什么东西放在哪"，不希望录入比收纳本身更费劲
- 寻找时：通过物品名称或缩略图快速定位到具体位置，不需要翻箱倒柜——也不需要打电话问收纳的那个人
- 日常中：工具安静存在，不主动打扰，需要时打开即用
- 家人之间：共用同一个物品库，任何人收纳的物品全家都能找到

### 2.3 Non-Users (v1)

- 搬家/资产盘点需求 —— 不在产品边界内
- 推送提醒依赖者 —— BoxWise 是被动响应式的，不推送
- 陌生人/访客 —— 需要家庭账户才能访问

### 2.4 Key User Journeys

- **UJ-1. 收纳一件物品。**
  - **Persona + context:** 用户刚整理完一个抽屉，想把几个不常用的东西收进储物箱。
  - **Entry state:** 已登录，在首页。
  - **Path:** 点击"录入" → 拍照或跳过 → （拍照分支：AI 识别预填；跳过分支：手动填写）→ 选择/确认位置（如：次卧 → 衣柜 → 上层收纳箱）→ 添加标签 → 确认入库。如果连续收纳，下一件自动继承上一件的位置。
  - **Climax:** 看到物品卡片生成——缩略图、名称、位置、标签一目了然。
  - **Resolution:** 回到首页，可继续录入或浏览已有物品。收纳完成时，信息也已记录完毕，全家可见。
  - **Edge case:** AI API 不可用时，自动切换为纯手动输入模式，用户手动填写物品名称和备注。

- **UJ-2. 寻找一件久违的物品。**
  - **Persona + context:** 用户想找一个半年前家人收起来的备用数据线，只记得大概叫什么但不记得放哪了。
  - **Entry state:** 已登录，在首页。
  - **Path:** 在搜索框输入"数据线" → 系统模糊匹配返回若干结果 → 看到缩略图和位置标签 → 点击查看详情 → 按位置指引找到实物。
  - **Climax:** 在缩略图列表中一眼认出那个物品，看到位置"书房 → 储物柜 → 电子配件箱"。
  - **Resolution:** 拿到实物。关闭 APP。

- **UJ-3. 浏览某个位置下的所有物品。**
  - **Persona + context:** 用户想看看"次卧衣柜上层"到底放了哪些东西。
  - **Entry state:** 已登录，在首页。
  - **Path:** 切换到浏览视图 → 按位置层级展开：次卧 → 衣柜 → 上层 → 看到该位置下所有物品的缩略图网格。
  - **Climax:** 一眼扫过就知道所有东西在哪。
  - **Resolution:** 可能顺便发现其他被遗忘的物品。关闭 APP 或继续浏览。

- **UJ-4. 家人首次使用。**
  - **Persona + context:** 家庭成员第一次打开 BoxWise，需要登录才能访问家庭物品库。
  - **Entry state:** 未登录，在登录页。
  - **Path:** 输入已创建的账号密码 → 登录成功 → 进入首页 → 看到家庭所有已录入物品的缩略图网格。
  - **Climax:** 登录后立即看到全家物品——不需要自己做任何录入就能用搜索和浏览。
  - **Resolution:** 可以搜索、浏览、录入新物品。关闭 APP 后会话保持，下次打开无需重新登录。
  - **Edge case:** 密码错误时给出提示，允许重试。 [ASSUMPTION: 不做密码重置流程——v1 由管理员（开发者）手动处理]

## 3. Glossary

- **物品（Item）** —— BoxWise 管理的最小单元。包含：照片、名称、位置、标签、备注、录入时间、录入者。一个物品只能在一个位置。所有家庭成员共享同一物品库。
- **位置（Location）** —— 物品的物理存放地。层级结构由用户自定义（如房间 → 柜子 → 箱子），深度不限。由用户自行创建和命名。叶子节点位置下挂物品。
- **标签（Tag）** —— 用户自定义的扁平分类标记，用于跨位置筛选（如"电子配件""工具""证件"）。一个物品可以有多个标签。
- **备注（Note）** —— 物品的补充文字描述。AI 识别结果预填至此字段，用户可编辑。
- **连续收纳（Continuous Storage）** —— 连续录入多件物品时，位置信息自动从上一件继承，无需重复选择。
- **AI 识别（AI Recognition）** —— 调用 OpenAI 兼容的多模态 LLM API，对物品照片进行分析，自动识别物品名称并生成备注描述。支持通过配置（base URL、模型名称、自定义字段）适配不同 OpenAI 兼容提供商（如 OpenAI 官方、火山方舟、Kimi、Qwen 等）。非 OpenAI 兼容的原生 API（如 Claude API、Gemini API）为后续版本。
- **账户（Account）** —— 家庭成员用于登录 BoxWise 的凭证。每个账户有独立的用户名和密码。所有账户共享同一个物品库，权限相同。 [ASSUMPTION: v1 所有成员权限相同，不做管理员/普通成员的角色区分]

## 4. Features

### 4.1 物品录入

**Description:** 核心录入流程。用户可选择拍照或跳过拍照直接录入。拍照后系统调用多模态 LLM API 识别物品并预填信息；跳过拍照则直接进入手动填写。用户确认/编辑信息后选择位置和标签，完成入库。此流程实现 UJ-1。AI API 不可用时降级为纯手动输入模式。[ASSUMPTION: AI 识别和手动输入共用同一录入界面，AI 失败时界面平滑切换而非跳转到另一个页面]

**Functional Requirements:**

#### FR-1: 拍照采集（可选）
用户可以选择拍摄物品照片或跳过拍照直接录入。照片为物品记录的可选字段。
**Consequences (testable):**
- 录入页顶部提供"拍照"按钮，表单始终可见。点击按钮调用设备后置摄像头，桌面端退化为文件选择器。
- 拍照后显示预览，用户可继续编辑表单信息；未拍照可直接填写，照片为可选字段。
- 无照片的物品在网格视图中显示文字卡片 + 占位图标。

#### FR-2: AI 识别预填
系统将物品照片发送至 OpenAI 兼容的多模态 LLM API，自动识别物品名称并生成简要描述，预填至备注字段。支持通过配置切换不同的 OpenAI 兼容提供商（base URL、模型名称、自定义额外字段）。
**Consequences (testable):**
- 拍照确认后自动触发 API 调用。
- API 返回物品名称和描述后预填至表单对应字段。
- API 调用期间显示加载状态。
- [ASSUMPTION: LLM API 调用在后端完成，前端不直接持有 API key]
- [ASSUMPTION: v1 固定使用单一模型，不做多模型 fallback——用户通过配置文件指定一个 OpenAI 兼容提供商]
- API 提供商通过后端配置文件切换（base URL + API key + model name + 自定义字段），无需修改代码。

#### FR-3: 手动输入兜底
当 AI API 调用失败、超时或不可用时，系统自动切换为纯手动输入模式。
**Consequences (testable):**
- AI 不可用时，物品名称和备注字段显示为空的可编辑文本输入框。
- 用户可以手动填写所有字段并完成录入。
- 切换过程不丢失已拍摄的照片。
- [ASSUMPTION: 超时阈值设为 15 秒——用户愿意等但不想等太久]

#### FR-4: 位置分配
用户为物品分配一个层级位置（房间 → 柜子 → 箱子）。
**Consequences (testable):**
- 用户可从已有位置层级中选择叶子节点。
- 用户可在录入流程中即时创建新位置。
- 位置为物品必填字段。

#### FR-5: 标签附加
用户可以为物品添加多个自定义标签。
**Consequences (testable):**
- 支持从已有标签中选择和即时创建新标签。
- 标签为可选字段。
- 一个物品可关联多个标签。

#### FR-6: 入库保存
用户确认所有信息后保存物品记录。
**Consequences (testable):**
- 保存后物品出现在浏览网格和搜索结果中。
- 保存成功后进入"连续收纳"状态（见 §4.2）。
- 必填字段（位置）未填时阻止保存并给出提示。

### 4.2 连续收纳

**Description:** 当用户在同一位置连续收纳多件物品时，系统自动继承上一件物品的位置信息，减少重复操作。实现 UJ-1 中的连续录入场景。

**Functional Requirements:**

#### FR-7: 位置继承
保存一件物品后，下一件物品录入时位置字段默认填充为上一件的位置。
**Consequences (testable):**
- 保存物品后，新录入表单的位置字段自动设为上一次选择的位置。
- 用户仍可手动更改位置，更改后新的位置成为后续继承值。
- 离开录入页面或刷新后，继承状态重置。

#### FR-8: 连续模式提示
UI 清晰标识当前处于"连续收纳"状态及继承的位置。
**Consequences (testable):**
- 录入表单顶部显示当前继承的位置名称（如"连续收纳至：次卧 → 衣柜 → 上层"）。
- 提供"退出连续模式"操作，清空继承的位置。

### 4.3 搜索

**Description:** 物品优先的搜索体验。用户输入物品名称关键词，系统模糊匹配并返回结果。实现 UJ-2。

**Functional Requirements:**

#### FR-9: 模糊搜索
用户可以通过物品名称关键词搜索物品，系统执行模糊匹配。
**Consequences (testable):**
- 搜索匹配物品名称、备注、标签字段。
- 支持部分匹配（如"线"匹配"数据线"）。
- 搜索结果按相关度排序。
- 搜索为空时显示空状态提示。

#### FR-10: 搜索结果展示
搜索结果以列表或网格形式展示，包含物品缩略图、名称、位置、标签。
**Consequences (testable):**
- 每条结果展示缩略图、物品名称、完整位置路径、标签。
- 点击结果进入物品详情页。
- [ASSUMPTION: 详情页仅展示物品全部信息，v1 不做编辑功能——编辑需求待验证后再加]

### 4.4 浏览

**Description:** 用户可以通过缩略图网格浏览所有物品，并按位置或标签筛选。实现 UJ-3 中的浏览需求。

**Functional Requirements:**

#### FR-11: 缩略图网格
所有物品以缩略图网格形式展示，便于视觉浏览。
**Consequences (testable):**
- 网格展示所有物品的缩略图。
- 每个缩略图卡片显示物品名称和位置摘要。
- 默认按录入时间倒序排列。
- [ASSUMPTION: 网格采用响应式布局，适配手机竖屏 2 列、平板/桌面 4-6 列]

#### FR-12: 位置筛选
用户可以按位置层级筛选物品显示范围。
**Consequences (testable):**
- 用户选择位置层级中任意节点，网格仅显示该位置及其子位置下的物品。
- 支持逐级展开/收起位置树。
- 显示当前筛选条件下的物品数量。

#### FR-13: 标签筛选
用户可以按标签筛选物品。
**Consequences (testable):**
- 显示所有已使用标签的列表及物品计数。
- 支持单选和多选标签组合筛选。
- 位置筛选和标签筛选可以叠加使用。

### 4.5 位置管理

**Description:** 用户可以创建和管理层级化的位置结构，支持按层级浏览物品。

**Functional Requirements:**

#### FR-14: 层级位置创建
用户可以创建、命名、编辑、删除层级位置节点，层级深度由用户自定义（如房间 → 柜子 → 箱子，或房间 → 柜子 → 抽屉 → 分隔盒等更深层级）。
**Consequences (testable):**
- 位置层级深度不限，由用户根据实际收纳结构自由创建。
- 创建位置时可选择父节点（如"次卧"下创建"衣柜"）。
- 删除非空位置时提示用户确认或阻止删除。
- 重命名位置不影响已关联物品的记录完整性。

#### FR-15: 层级浏览
用户可以在浏览视图中按位置层级导航查看物品。
**Consequences (testable):**
- 位置以可展开/收起的树形结构展示。
- 点击叶子节点展示该位置下的物品网格。
- 点击非叶子节点展示该位置下所有子位置的物品汇总。

### 4.6 物品删除

**Description:** 用户可以从物品详情页删除不再需要的物品记录。

**Functional Requirements:**

#### FR-16: 物品删除
用户可以在物品详情页删除物品记录。
**Consequences (testable):**
- 物品详情页提供删除按钮。
- 点击删除后弹出确认对话框。
- 确认后删除数据库记录及关联的照片文件。
- 删除后返回上一页（浏览网格或搜索结果），该物品不再出现。

### 4.7 账户认证

**Description:** 家庭成员通过账户登录使用 BoxWise。所有成员共享同一物品库，权限相同。实现 UJ-4。

**Functional Requirements:**

#### FR-17: 用户注册
管理员通过后台管理界面创建家庭成员账户。不提供面向最终用户的自助注册功能（后续版本也不做）。
**Consequences (testable):**
- 后台管理界面提供创建账户功能，需填写用户名和密码。
- 用户名在系统内唯一。
- 无公开的自助注册入口——这是家庭内部使用的定位，非公共服务。

#### FR-18: 用户登录
已注册用户可以通过用户名和密码登录系统。
**Consequences (testable):**
- 登录页为未认证用户的默认入口。
- 输入用户名和密码，验证通过后进入首页。
- 密码错误时给出提示。
- 登录成功后会话保持，关闭浏览器后再次打开无需重新登录（Persistent Cookie/Token）。
- [ASSUMPTION: 采用基于 Cookie 或 Bearer Token 的简单会话机制，不做 OAuth/第三方登录]

#### FR-19: 登录保护
所有物品相关页面（浏览、搜索、录入、详情）需要登录后才能访问。
**Consequences (testable):**
- 未登录用户访问任何功能页面时重定向至登录页。
- API 端点在未认证时返回 401。
- 登录后重定向回用户原本要访问的页面。

#### FR-20: 录入者标识
物品记录显示录入者信息，便于家人知道"这是谁收的"。
**Consequences (testable):**
- 物品详情页显示录入者用户名。
- 浏览网格可选显示录入者。
- [ASSUMPTION: 录入者仅作信息展示，不影响权限——任何成员都可以删除任何物品]

**Feature-specific NFRs:**
- 密码通过 ASP.NET Core Identity 内置的哈希算法安全存储。

**Notes:**
- 后台管理界面的账户管理为 v1 必需功能，至少包含：创建账户、列表查看已有账户。

## 5. Non-Goals (Explicit)

- **不是搬家工具** —— 不做物品状态追踪、损坏记录、搬家清单
- **不是资产管理** —— 不做价格、购买日期、保修期、发票管理
- **不是断舍离助手** —— 不做使用频率统计、闲置提醒、舍弃建议
- **不是社交平台** —— 不做陌生人分享、公开链接、社区功能
- **不做权限细分** —— v1 所有成员权限相同，不做管理员/普通成员角色
- **不做主动推送** —— 不发送任何形式的提醒通知
- **不做平面图/空间可视化** —— 位置用纯文字标签，不画图
- **不做数据统计面板** —— 不统计物品数量趋势、标签分布图等

## 6. MVP Scope

### 6.1 In Scope

- 物品拍照录入 + AI 识别 + 手动兜底
- 物品删除（详情页删除按钮 + 确认对话框）
- 层级位置管理（用户自定义深度）
- 标签系统
- 连续收纳模式
- 模糊搜索
- 缩略图网格浏览
- 位置 + 标签筛选
- 账户系统（后台管理界面创建账户、登录、会话保持、录入者标识）
- 家庭成员共享同一物品库
- PWA 安装到桌面 + 离线缓存展示
- SQLite 数据库
- ASP.NET Core 后端（含 ASP.NET Core Identity 认证）+ Blazor WASM 前端
- Linux VPS 部署 + HTTPS

### 6.2 Out of Scope for MVP

- 物品编辑功能 —— 待 v2 验证需求
- 非 OpenAI 兼容的原生 API（Claude API / Gemini API 等）—— 后续版本兼容
- 多模型 fallback / 负载均衡 —— v1 固定单一模型
- OAuth/第三方登录 —— 仅用户名+密码
- 自助注册页面 —— 后续版本也不做，家庭内部使用定位
- 角色权限细分（管理员/普通成员）—— v1 全员相同权限
- 批量导入/导出
- 数据迁移/备份工具

## 7. Success Metrics

*家庭使用项目，成功标准为定性体验指标。*

**Primary**
- **SM-1**: 家庭使用留存 —— 搬家/换季整理后至少两个家庭成员实际使用。目标：3 个月内至少 2 次收纳场景使用。
- **SM-2**: 找物成功率 —— 任何家庭成员需要找东西时，通过 BoxWise 在 30 秒内定位到实物。目标：非第一次使用的找物场景，成功率 > 90%。
- **SM-3**: 家庭覆盖 —— 至少 2 个家庭成员完成过登录并使用（搜索或录入）。验证多人场景价值。

**Secondary**
- **SM-4**: 录入效率 —— 单件物品录入时间 < 20 秒（含拍照和 AI 等待）。验证连续收纳模式的价值。

**Counter-metrics (do not optimize)**
- **SM-C1**: 物品录入数量 —— 不应追求录入更多物品。BoxWise 的价值在于找到需要的东西，不在库存规模。
- **SM-C2**: 使用频率 —— 不应追求 DAU/MAU。找东西是低频需求，低频使用恰恰说明收纳做得合理。

## 8. Cross-Cutting NFRs

### 8.1 Performance
- 目标部署环境为 1C1G Linux VPS，用户数 ≤ 5。所有性能指标基于此基准。
- 物品列表（含缩略图）首屏加载 < 2 秒（100 件物品以内）
- 缩略图懒加载，避免一次性加载全量原图
- 搜索响应 < 500ms

### 8.2 Security
- 使用 ASP.NET Core Identity 进行认证和用户管理
- 密码使用 Identity 内置的哈希算法存储
- 所有 API 端点（除登录外）要求认证
- 会话 Cookie 设置 HttpOnly 和 Secure 标志
- 部署时启用 HTTPS（通过云平台或反向代理如 Caddy/Nginx 的免费 TLS 证书）

### 8.3 PWA / Offline
- PWA 符合安装条件（manifest、service worker、图标）
- 离线时展示已缓存的物品列表和缩略图（只读）
- 离线时录入操作不可用——恢复连接后同步
- [ASSUMPTION: Service Worker 缓存策略为 Stale-While-Revalidate——缓存优先保证离线速度，后台更新保证数据新鲜]

### 8.4 AI Reliability
- AI API 调用超时时间 15 秒
- API 不可用时 UI 平滑降级为手动输入，不阻塞录入流程
- API 调用失败不在 UI 层报错，仅静默切换模式
- v1 固定使用单一模型，不做多模型 fallback——用户通过配置文件指定一个 OpenAI 兼容提供商

### 8.5 Data
- 数据库单文件 SQLite，存储于服务端
- 图片存储于服务端文件系统，数据库仅存路径
- 图片大小和总量不做硬性限制
- [ASSUMPTION: Linux VPS 部署使用持久化存储卷，避免容器重启丢失数据]
- v1 无自动备份机制——由开发者定期手动备份数据库文件和图片目录

## 9. Platform

- **形态**: PWA（Progressive Web Application）
- **前端**: Blazor WASM，响应式布局适配手机/平板/桌面
- **后端**: ASP.NET Core Web API + ASP.NET Core Identity
- **数据库**: SQLite + EF Core
- **部署**: Linux VPS（目标 1C1G，用户数 ≤ 5），单机容器化或直接运行
- **反向代理**: Caddy / Nginx，自动管理 TLS 证书
- **PWA 能力**: 安装到桌面、Service Worker 离线缓存、无推送通知
