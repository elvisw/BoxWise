# Decision Log — BoxWise PRD

## Session: 2026-05-21 (PRD Creation)

### D-1: 位置模型 — 层级结构
**Decision:** 采用 3 层层级结构（房间 → 柜子 → 箱子），支持按层级浏览。
**Source:** 用户确认（快速模式问答 #1）
**Rationale:** 层级结构匹配用户收纳时的物理组织方式，浏览体验更直观。

### D-2: AI 识别降级 — 手动兜底
**Decision:** 多模态 LLM API 不可用时，纯手动输入物品名称和备注，不阻塞录入流程。
**Source:** 用户确认（快速模式问答 #2）
**Rationale:** 录入流程不应依赖外部服务可用性；AI 是增强而非必需品。

### D-3: PWA 离线 — 缓存展示 + 在线同步
**Decision:** 离线时缓存展示已有物品（只读），录入不可用，恢复连接后同步。
**Source:** 用户确认（快速模式问答 #3）
**Rationale:** 找东西是核心场景，离线时能看比能录更重要。录入需要图片上传，离线场景意义不大。

### D-4: 技术栈 — C# 全栈
**Decision:** Blazor WASM (PWA) + ASP.NET Core + SQLite + EF Core + 文件系统图片存储。
**Source:** 头脑风暴方案矩阵（2026-05-21）
**Rationale:** 用户 C# 技术栈，全栈类型安全，SQLite 单文件零配置适合个人部署。

### D-5: 产品边界 — 只做"找东西"
**Decision:** 不扩展搬家、资产管理、断舍离、社交共享、推送通知、平面图可视化、数据统计。
**Source:** 头脑风暴 SCAMPER 结果（2026-05-21）
**Rationale:** 聚焦单一问题，最小够用。

### D-6: 工作模式 — 快速模式
**Decision:** 采用快速模式（Fast Path）创建 PRD，合并关键问题一次性澄清。
**Source:** 用户选择（2026-05-21 PRD 会话）
**Rationale:** 头脑风暴已产出充分素材，剩余不确定点少。

### D-7: 录入后编辑功能 — 推迟至 v2
**Decision:** v1 物品详情页只做展示不做编辑；编辑功能待需求验证后加入 v2。
**Source:** PRD 内联假设（FR-10）
**Rationale:** 个人使用场景中录入错误可在录入时修正；编辑的复杂度（照片更换、位置迁移历史）需要更多设计。

### D-8: 物品删除 — v1 加入
**Decision:** v1 在物品详情页加入删除按钮 + 确认对话框，删除记录同时清理照片文件。
**Source:** 用户确认（2026-05-21 PRD 定稿阶段）
**Rationale:** 删除是最基本的操作预期，实现成本低（一个 API 端点 + 确认弹窗），不值得为此操作数据库。

### D-9: PRD 定稿（第一版）
**Decision:** PRD 于 2026-05-21 定稿（第一版），status 设为 final。剩余 3 个 Open Questions 为非阻塞项。
**Source:** PRD 定稿流程（2026-05-21）
**Rationale:** LLM API 选型、图片存储上限、位置层级深度均不影响架构设计——可在实现时根据实际情况决定。

### D-10: 范围变更 — 个人→家庭 + 公有云
**Decision:** 范围从"个人使用/本地部署"调整为"家庭使用/公有云部署"。新增账户认证功能（FR-17~FR-20），新增 Security NFRs，部署目标改为公有云。
**Source:** 用户要求（2026-05-21 PRD 更新）
**Rationale:** 家庭成员也需要使用；公有云部署需要身份认证保护。物品库家庭内共享，所有成员权限相同。

### D-11: 自助注册 — 永久不做
**Decision:** 不提供面向最终用户的自助注册页面，后续版本也不做。账户仅通过后台管理界面由管理员创建。
**Source:** 用户要求（2026-05-21 PRD 更新 #2）
**Rationale:** 家庭内部使用定位，非公共服务。避免暴露注册入口给公网。

### D-12: 技术决策批量确认
**Decision:** 认证使用 ASP.NET Core Identity、部署目标 Linux VPS（兼容低配置）、位置层级深度由用户自定义（不限 3 层）、图片不做大小/总量限制。
**Source:** 用户要求（2026-05-21 PRD 更新 #2）
**Rationale:** 用户明确确认，移除对应的 Open Questions 和 Assumptions。

### D-13: LLM API — 多模型兼容需求
**Decision:** LLM API 需兼容国际主流（OpenAI/Claude/Gemini）及国产多模态大模型（火山方舟、Kimi、Qwen）。多模型切换策略待定。
**Source:** 用户要求（2026-05-21 PRD 更新 #2）
**Rationale:** 降低单模型依赖风险，增加国内可访问性。

### D-14: LLM API — OpenAI 兼容 + 可配置切换 + 固定单模型
**Decision:** v1 支持所有 OpenAI 兼容接口（OpenAI 官方 + 国产模型如火山方舟/Kimi/Qwen），通过配置文件切换 base URL、模型名称、自定义额外字段，无需修改代码。固定单一模型不使用 fallback。非 OpenAI 兼容原生 API（Claude/Gemini）为后续版本。
**Source:** 用户确认（2026-05-21 PRD 更新 #3, #4）
**Rationale:** 国产大模型几乎全部兼容 OpenAI 接口，通过可配置化即可覆盖，无需额外集成工作。非兼容原生 API 需独立适配，推迟到后续版本。

### D-15: 拍照录入 — 改为可选
**Decision:** FR-1 从"必须拍照"改为"拍照可选"。用户可跳过拍照直接填写物品名称+位置+标签，无照片物品在网格中显示文字卡片+占位图标。
**Source:** 用户要求（UX 设计过程中）
**Rationale:** 部分物品不需要照片（如已知名称的线缆/配件），跳过拍照可加快录入速度。不涉及新的存储或架构需求。

### D-16: 部署基准 — 1C1G VPS / ≤5 用户
**Decision:** 目标部署环境为 1C1G Linux VPS，用户数不超过 5。所有性能指标基于此基准验证。
**Source:** 用户确认（2026-05-21 PRD 更新 #3）
**Rationale:** 家庭使用场景，极端低配验证可确保资源效率。Blazor WASM + ASP.NET Core + SQLite 在 1C1G 下的可用性需在实现阶段验证。
