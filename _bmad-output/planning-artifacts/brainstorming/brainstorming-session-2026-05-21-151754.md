# 头脑风暴会话结果

**引导者:** AI Facilitator
**日期:** 2026-05-21

## Session Overview

**主题:** 不常用物品收纳后找不到的解决方案 - 箱知 · BoxWise (PWA Web APP)
**目标:** 探索用后端+PWA架构的Web APP解决"收纳后过很久找不到东西"问题的可行性、核心功能、用户体验和技术方案

### Session Setup

用户提出了一个痛点：不常用的东西收纳起来后，过了很久想用它但是找不到了。用户希望探讨是否可以开发一个基于**后端 + PWA 架构**的 Web APP 来解决这个问题，APP 命名为 **箱知 · BoxWise**。

这是一个典型的"物品定位与管理"问题。本次头脑风暴将从用户痛点出发，探索产品核心价值、关键功能、技术方案和差异化竞争点。

### Five Whys 结果

**因果链：**
> 找不到 → 因为放在太"安全"/隐蔽的地方
> → 因为收的时候没有建立找回机制
> → 因为相信自己凭记忆就能找到
> → 因为低估了"不常用 = 记忆衰减"的自然规律
> → **根因：人脑没有记忆过期提醒机制，收纳是一次性、无反馈闭环的动作**

**核心洞察：** 问题不在于收纳得不好，而在于收纳的完成时刻就是信息丢失的开始。解决方案必须在那个时刻介入，代偿人脑做不到的两件事：**持久记录** 和 **适时提醒**。

### SCAMPER 结果

| 透镜 | 决策 | 说明 |
|------|------|------|
| **S** 替代 | ✅ 数字记录替代人脑记忆 | 拍照 + 位置 + 备注 = 最小记录单元 |
| **C** 组合 | ✅ 拍照 + 多模态 LLM 自动识别 | 拍照时自动识别物品，预填备注 |
| **A** 适配 | ✅ 借鉴三大模式 | 图书分类法 + 快递追踪 + 密码管理器逻辑 |
| **M** 增强 | ✅ 三项增强 | 连续收纳模式、标签+emoji+文字、搜索+缩略图浏览 |
| **P** 他用 | ❌ 不做 | 搬家/资产/断舍离等扩展场景全部排除 |
| **E** 消除 | ❌ 四项消除 | 不要提醒推送、不要平面图可视化、不要账户系统(本地)、不要数据统计 |
| **R** 翻转 | ✅ 物品优先 | 搜物品名直达，而非按位置层级浏览 |

**核心流程：**
- **收纳时：** 拍照 → 多模态 LLM 识别物品 → 选择/确认位置 → 标签+文字备注 → 入库
- **寻找时：** 搜索物品名 OR 浏览缩略图 → 看到位置标签 → 按指引找到实物

### 方案矩阵结果

| 维度 | 选择 |
|------|------|
| **后端** | C# / ASP.NET Core |
| **数据库** | SQLite + EF Core |
| **图片存储** | 文件系统 + 数据库存路径 |
| **前端** | Blazor WASM (PWA) |
| **AI 识别** | 多模态 LLM API 调用 |
| **部署** | 个人使用，本地/局域网部署 |

## 想法整理与主题聚类

### 主题 1：产品边界与定位

- **只做"找东西"一件事** —— 不扩展到搬家、资产清单、断舍离
- **被动响应式** —— 用户来找它，它不主动推送/提醒
- **个人使用** —— 无需账户系统、共享功能
- **轻量务实** —— 最小够用，拒绝功能膨胀

### 主题 2：核心功能

| 功能 | 描述 |
|------|------|
| **物品录入** | 拍照 → LLM 自动识别 → 选位置 → 标签+备注 → 入库 |
| **连续收纳** | 同一位置连续录入，默认继承上一个位置，减少重复操作 |
| **多模态识别** | 调用多模态 LLM API，拍照即识别物品名称，预填备注字段 |
| **搜索** | 按物品名搜索（物品优先），支持模糊匹配 |
| **浏览** | 缩略图网格浏览，按位置/标签筛选 |
| **位置管理** | 文字标签描述位置（房间/柜子/箱子），无需平面图 |

### 主题 3：技术架构

| 层 | 技术 | 理由 |
|----|------|------|
| **前端** | Blazor WASM (PWA) | C# 全栈，用户掌握；PWA 模板支持离线+安装到桌面 |
| **后端** | ASP.NET Core Web API | C# 全栈，编译时类型安全，维护成本低 |
| **数据库** | SQLite + EF Core | 单文件零配置，个人使用理想选择 |
| **图片** | 文件系统 + 路径 | 简单直接，SQLite 不存 blob |
| **AI** | 多模态 LLM API | 拍照识别物品，成本可接受 |
| **部署** | 本地/局域网 | 个人使用，无需云部署 |

### 关键突破

- **根本矛盾：** "因为重要所以藏得深"——安全放置行为本身导致了不可找回
- **设计哲学：** 收纳完成时刻即是信息丢失开始的时刻，工具必须在那一刻介入
- **解决思路：** 不依赖记忆，依赖持久化数字化记录 + 物品优先的检索方式
