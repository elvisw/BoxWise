# Decision Log — SPEC-fix-thumbnail-generation-resilience

## 2026-06-05 — Initial creation

### Pass 1 — Coherence

Rule-by-rule sweep:

1. **Intent + success per capability** ✅ — All 4 capabilities have both fields. CAP-1 through CAP-4 each describe observable, testable outcomes.
2. **Intent describes WHAT, not HOW** ✅ — CAP-1 says "eliminate system dependency", not "change Directory.Packages.props line 23". CAP-3 says "BackgroundService-managed persistent queue", which borders on HOW — judged acceptable because the mechanism (BackgroundService vs fire-and-forget) is itself the specification of the new behavior, not an implementation detail.
3. **Constraints bend design** ✅ — "不改变存储布局" rules out alternative storage schemes. "不引入新的外部服务依赖" rules out Redis/RabbitMQ-backed queues. "进程内内存队列" is a consequence of that constraint.
4. **Non-goals explicit** ✅ — Four items covering migration, manual UI, version change, and upload retry. All are reasonable things a downstream implementer might try; all are explicitly excluded.
5. **Success signal concrete** ✅ — Describes a specific world-change: deploy on clean Debian → upload → see thumbnail → delete files → restart → thumbnail recovers. Testable end-to-end.
6. **Capability IDs stable and unique** ✅ — CAP-1 through CAP-4, first creation, no reuse possible.
7. **Preservation** — See Pass 2.
8. **Lean prose** ✅ — No decoration, no backstory beyond the Why paragraph, no hedges.

### Verdict

SPEC is coherent and preservation-validated. Four capabilities cover the root cause elimination (CAP-1), resilience gap (CAP-2 + CAP-3), and documentation gap (CAP-4). Both open questions resolved:

1. Recovery scan concurrency: global `SemaphoreSlim(2, 2)` shared with upload path — lightweight cap that prevents CPU saturation without complexity cost.
2. Docker base image fontconfig status: confirmed `mcr.microsoft.com/dotnet/aspnet:10.0` (Ubuntu Noble) does NOT include `libfontconfig1`. CAP-1 fully beneficial for both Docker and binary deployments.

### Verdict after Update 3

SPEC 经历两轮对抗性评审（共 24 条发现）后稳定。关键设计决策：
- **NoDependencies** 消除系统依赖（Dockerfile 零变更）
- **周期扫描不重叠**（轻量标记保护）
- **恢复串行**（SemaphoreSlim(1,1)）不给 CPU 施压
- **优雅关闭接受两种结果**——不伪装能保证完成
- **单消费者循环**——简单可靠，per-item 锁防护恢复路径竞争
- **字典泄漏明确标注为已知限制**——家用规模可接受

### Verdict after Update 5

SPEC 经历四轮对抗性评审（共 **39 条**发现）后达到稳定状态。v5 的核心收敛：
