# 决策日志

## 2026-05-27 — 初始创建

### 关键决策

1. **ThumbnailService 降级为手动验证。** 原因：`GenerateInBackground` 使用 `Task.Run` + `IServiceScopeFactory` 解析 DbContext + SkiaSharp 位图操作，单元测试需要 mock 整个 ASP.NET Core DI 容器和 SkiaSharp 位图 API，投入产出比低。它的核心逻辑在 ImageEndpoints 集成测试中会被间接覆盖。

2. **ImageEndpoints/AiEndpoints 降级优先级。** 原因：ImageEndpoints.UploadAsync 需要构建 `IFormFile` mock（含 Stream/ContentType/FileName 等），AiEndpoints 依赖外部 LLM HTTP 调用的完整 mock 链。两者计为 CAP-3 的可选加分项，不纳入最低验收线。

3. **85 为保守目标，100+ 为实际目标。** SPEC.md Success signal 写 ≥ 85 是合理底线（所有 P0 覆盖），test-inventory.md 中的 100+ 是完整覆盖的预期值。

4. **不修改现有测试。** 52 个现有测试保持原样，仅删除死代码 UnitTest1.cs。修改现有测试的断言会增加验证范围，不符合"纯补充"的约束。

5. **"方法全覆盖" > "分支全覆盖"。** 约束中写"不追求覆盖率百分比"并非降低标准，而是强调有效测试：每个方法有 happy-path + 异常路径测试，不分心追逐数字指标。

6. **测试组织保持现有结构。** Repository 测试继续放在 `Repositories/` 子目录。Endpoint/Service 测试新建对应子目录 `Endpoints/`、`Services/`，遵循现有模式。
